# 화면별 사용 안내

## Mac·iPad·iPhone에서 Incoming으로 업로드

**기기에서 업로드 → 사진·파일 선택**에서 사진 보관함·파일 앱·Finder 파일을 여러 개 고른다. 저장할 하위 폴더는 선택 사항이며 Mac에서는 폴더를 드롭하여 내부 구조를 유지할 수도 있다. 폴더는 6단계·180자 이내, 한 번에 최대 2,000개 파일을 처리한다. 숨김 드롭 항목은 제외한다.

iPhone·iPad 사진 보관함에서 원본 화질(HEIC·MOV)을 유지하려면 선택 화면 ‘옵션’에서 ‘현재 항목’을 선택하세요.

JPG·JPEG·PNG·WEBP·HEIC·HEIF·MP4·MOV와 동반 XMP·THM·LRV를 지원한다. DNG 등 미지원 형식과 빈 파일은 결과에 제외 이유를 남기고 나머지를 계속 처리한다. 사진 → 영상 → 동반 파일 순으로 업로드하며 기존 파일과 이름이 겹치면 (1) 등 번호를 붙인다. 같은 배치의 원본 개명에 맞춰 동반 파일 이름도 조정하되 원본 stem이 여러 개인 경우 단순 stem 리매핑은 생략한다.

패널과 상단 알약에서 진행률을 확인하고 **중지**를 누르면 현재 임시 업로드와 대기 파일을 취소한다. 이미 완료한 파일은 보존한다. 일시적 청크 통신 오류는 서버 오프셋을 확인해 최대 두 번 재시도한다. 전송 중에는 탭을 열어 두고 기기 절전/앱 전환을 피한다. 화면 잠금 방지는 브라우저가 허용하는 경우에만 적용되며 새로고침 뒤 자동 재개는 제공하지 않는다.

기본으로 **완료 후 파일 검사**가 켜져 있다. 성공한 파일이 있으면 로컬 작업이 비었을 때 검사를 시작하고 로컬 작업 진행 중이면 끝난 뒤 **파일 검사**를 누르라는 안내를 표시한다. 원격 전송과 기기 업로드는 함께 실행할 수 있고 데이터 초기화 중에는 새 업로드가 차단된다. 패널은 화면 갱신 중 파일 입력·폴더 포커스와 결과 펼침 상태를 유지한다.


이 문서는 현재 [프론트엔드](../frontend/app.js)와 [API](../backend/api.py)에 구현된 화면 동작을 설명한다. 실행 후 기본 주소인 `http://127.0.0.1:8888`에서 접속한다.

## 페이지와 기본 흐름

| 메뉴 | URL 해시 | 용도 |
| --- | --- | --- |
| Incoming Library | `/#incoming` | 로컬 파일 검사, 이동, 사진 삭제, XMP 연결 |
| 이벤트 관리 | `/#events` | 보관 파일의 이벤트 배정, 장비·시각 보정, 배치 확정 |
| 아카이브 전송 | `/#archive` | 확정 배치와 원격 폴더 탐색, 업로드 |
| 파일 기록 | `/#catalog` | 파일 해시와 전송 검증 이력 조회 |
| 설정 | `/#settings` | SSH 연결 정보, 키, 카탈로그 백업·복원 |

처음 접속하거나 알 수 없는 해시를 사용하면 Incoming Library가 열린다. 일반적인 사용 순서는 **incoming에 파일 복사 → 검사 → managed로 이동 → 이벤트 배정·확정 → 아카이브 연결·업로드 → 파일 기록 확인**이다. 원격 스토리지 연결 없이도 로컬 검사와 이벤트 분류를 진행할 수 있다.

## Incoming Library

### 검사와 파일 선택

1. 운영체제에서 사진·영상을 incoming에 넣거나 **기기에서 업로드**를 사용한다.
2. **파일 검사**를 누른다. 화면에서 기존 보관 파일 확인, Incoming 해시 검사, 썸네일 생성 등 현재 처리 단계를 본다. 결과에는 Incoming 기준 경로, 수정 일시, 크기, 썸네일과 결과 사유가 표시된다.
3. **전체 / 이동 가능 / 중복 / 확인 필요**로 결과를 좁히고 **모든 형식 / 사진 / 영상**을 선택한다. 검색은 파일명, 폴더와 XMP의 제목·설명·키워드·장소·GPS·기록 시각을 대상으로 한다.
4. 이동할 신규 항목을 선택하고 **선택 항목을 managed로 이동**을 누른다. 이동은 선택에서 **이동 가능**인 파일에 적용한다.

**이동 가능**과 **중복**인 사진·영상에 선택 상자가 있다. **모두 선택**과 일괄 작업은 현재 상태·형식·검색 조건에 표시된 선택 가능 항목에 적용된다. 필터나 검색으로 숨겨진 파일은 선택에서 빠진다.

**표 보기 / 카드 보기**를 전환할 수 있으며, 이 보기 설정은 브라우저의 로컬 저장소에 보관한다. 새로 추가하거나 변경한 파일은 다시 **파일 검사**로 확인한다. 최근 작업 결과에서 이동·정리·보류 상태를 확인하고, 이동한 파일은 **이벤트 관리 → 미배정**에서 이어서 분류한다.

### 중복 정리

**중복**인 사진 또는 영상을 선택하고 **중복 정리**를 누른다. 같은 SHA-256 그룹의 정리할 경로·용량과 남길 사본 후보를 확인한다. 후보가 여러 개면 사용할 사본을 고른다. 같은 Incoming 그룹의 파일을 남기기로 하면 해당 파일은 정리 목록에서 빠진다.

워커가 Incoming 파일과 남길 사본의 내용을 확인한 뒤 정리 대상으로 승인한 Incoming 미디어만 영구 삭제한다. OMV 사본을 고르면 현재 설정된 아카이브에서 실제 파일의 SHA-256을 대조한다. 파일이 변경됐거나 사본을 확인할 수 없는 경우는 **확인 필요**로 남는다. XMP·THM·LRV는 확인창에서 보존 상태를 확인할 수 있으며, 별도 XMP 연결 과정에서 처리할 수 있다.

### 원본 미리보기와 사진 삭제

썸네일을 누르면 큰 미리보기가 열린다. 사진은 이미지로, 영상은 브라우저 재생기로 표시하며 **원본 열기**는 새 탭에서 파일을 연다. 미리보기에서 경로와 중복 근거를 확인하고 현재 파일을 선택하거나 해제할 수 있다. HEIC·HEIF 미리보기는 JPEG로 변환하고, 영상 재생 가능 여부는 브라우저 코덱 지원에 따른다. 검사 후 파일이 변경되거나 이동되면 **파일 검사**로 상태를 다시 확인한다.

| 위치 | 키 | 동작 |
| --- | --- | --- |
| 카드의 썸네일에 포커스 | 방향키 | 카드 간 포커스 이동 |
| 카드의 썸네일에 포커스 | `Enter` | 미리보기 열기 |
| 카드 또는 미리보기 | `Delete` / `Backspace` | 삭제 가능한 사진의 삭제 확인 열기 |
| 미리보기 | `←` / `→` | 현재 필터의 미리보기 가능한 이전·다음 파일 표시 |
| 삭제 확인 | `Enter` | 포커스된 버튼 실행. 확인을 열면 취소에 포커스 |
| 미리보기 삭제 확인 | `Esc` | 삭제 확인 취소 |
| 미리보기 | `Esc` | 미리보기 닫기 |

영상 재생기에 포커스가 있을 때 좌우 방향키는 재생 위치를 제어한다. **이동 가능** 상태의 불필요한 사진은 **사진 삭제**로 Incoming에서 영구 삭제할 수 있다. 중복 사진은 **중복 정리**를 사용한다. 목록에서 여러 사진을 선택하면 대상 경로를 확인하는 대화상자가 열린다. 미리보기에서 한 장씩 삭제하면 삭제 후 다음 파일로 이동하고, 남은 파일이 없으면 미리보기가 닫힌다.

### XMP 연결

검사에서 함께 발견한 XMP와 THM·LRV는 해당 원본에 처리 상태와 함께 표시된다. 이동 가능한 원본에 연결된 XMP도 함께 보관하며, 짝이 확실한 THM·LRV는 원본 이동이 완료된 후 정리한다. 중복 정리와 연결이 불확실한 경우에는 동반 파일을 보존한다. 상세 연결 규칙은 [수집·분석 문서](media-pipeline.md)를 참고한다.

이미 managed에 원본이 있는 XMP 후보는 하단 **XMP 연결** 표에 나타난다. 기록된 시각과 원본 후보를 확인하고 **선택한 XMP 연결**을 실행한다. 같은 원본에 여러 XMP를 선택하면 실행 버튼이 비활성화된다. 연결할 수 없는 파일은 사유를 확인한다.

## 이벤트 관리

### 생성과 기간 배정

왼쪽 목록의 **전체 파일**은 managed의 사용 가능한 파일 전체를, **미배정**은 이벤트에 속하지 않은 파일을 보여 준다. 최상위 이벤트의 파일 수에는 소분류 파일도 포함하지만, 해당 이벤트를 눌렀을 때 오른쪽 목록에는 직접 배정된 파일만 표시한다.

**이벤트 생성**에서 이름, 시작일, 종료일, 촬영일 기준 시간대를 지정한다. **생성하고 파일 모으기**를 누르면 시각이 확인된 미배정 파일 중 기간에 맞는 파일을 자동으로 배정한다. 시작일과 종료일을 모두 포함하며, 여러 최상위 이벤트 기간에 겹치거나 촬영 시각 확인이 필요한 파일은 미배정에 남는다. 이후 **기간으로 모으기**를 다시 실행할 수 있다.

최상위 이벤트의 폴더명에는 `YYMMDD_` 시작일이 붙는다. 이름이 같은 날짜 접두사로 시작하면 한 번만 붙인다. 예를 들어 시작일이 `2026-09-03`인 `제주여행`은 `260903_제주여행`으로 표시된다.

시간대 선택 목록은 앱 기본 시간대와 `Asia/Seoul`, `Asia/Tokyo`, `Asia/Singapore`, `Europe/Paris`, `America/Los_Angeles`, `UTC`로 구성된다. 저장된 이벤트의 기존 시간대도 목록에 유지된다.

### 수동 배정, 소분류, 정보 보정

- **소분류 추가**는 최상위 이벤트 아래 한 단계만 지원한다. 소분류는 이름만 입력하며 기간과 시간대는 부모 이벤트를 기준으로 표시한다.
- 파일을 선택하고 하단 **이동할 이벤트**에서 목적지를 골라 **이동**한다. 미배정 파일의 최초 배정, 다른 이벤트 이동, 소분류 분배, 부모 이벤트로 되돌리기에 같은 동작을 사용한다. 실제 managed 파일 경로를 옮기지 않고 배정만 변경하며, 다른 이벤트로 이동한 파일은 초안이 된다.
- 검색은 파일명·장비·XMP 정보를 대상으로 하고, 보관 위치(`모든 위치 / 로컬 보유 / 아카이브 보관`)·장비·촬영일 필터를 함께 사용할 수 있다. 장비 필터에서 **장비 확인 필요**를 선택하면 장비명이 없는 사진·영상만 표시한다. 직접 `unknown` 등으로 지정한 파일은 해당 장비로 분류되므로 이 항목에서 제외한다. 전체 파일·미배정·이벤트·소분류에서 동일하게 사용할 수 있고, 필터를 바꾸면 기존 선택을 해제한다. 촬영일은 선택한 이벤트 또는 부모 이벤트의 시간대를 따른다.
- **장비·촬영 시각 수정**으로 여러 파일을 한 번에 보정한다. **촬영 장비**에서 전체 보관 파일에 사용 중인 장비명을 선택하거나 **직접 입력**으로 새 이름을 지정한다. 촬영 시각의 기본값은 **변경하지 않음**이므로 장비만 배정할 수 있다. 직접 시각을 입력하거나 EXIF·영상 메타데이터, XMP, 파일 수정 시각을 선택할 수도 있다.
- **XMP 시각 사용**은 선택 파일 중 사용할 수 있는 XMP 시각이 하나 이상 있으면 활성화된다. 적용 가능 개수와 파일별 XMP 시각·출처를 미리 보여 준다. XMP가 없거나 촬영 시각이 없는 파일은 기존 시각을 유지한다. 장비와 함께 적용하면 장비는 선택한 전체 파일에, XMP 시각은 사용할 수 있는 파일에 각각 적용한다. 완료 메시지에 시각 적용·유지 개수를 표시한다. EXIF·영상 메타데이터와 수정 시각 출처는 기존처럼 모든 선택 파일에 값이 있어야 한다. 연결된 XMP를 외부에서 수정했으면 **Incoming Library → 파일 검사**로 다시 읽은 뒤 적용한다.
- 시간대 없는 메타데이터에는 선택한 시간대를 적용한다. 여러 파일에 메타데이터 또는 수정 시각을 적용하면 각 파일의 고유 시각을 사용하며, 직접 입력한 시각은 선택 파일 모두에 동일하게 적용된다.
- 촬영 시각 확인이 필요한 행의 **촬영 시각 지정**으로 출처를 선택한다. XMP가 있으면 **XMP 정보**에서 제목, 설명, 시각, 키워드, 장소, GPS와 분석 상태를 확인한다.

장비를 수정하면 해당 파일의 배치 확정이 해제된다. 시각을 보정해도 기존 이벤트 배정은 유지되며, 다른 이벤트로 자동 재배정되지 않는다.

### 배치 확정과 이벤트 수정·삭제

이벤트에 배정한 로컬 파일을 선택하고 **선택 배치 확정**을 누른다. 대화상자의 이벤트·장비·파일 경로를 확인한 뒤 확정하면 아카이브 전송의 Source에 표시된다. 장비를 찾지 못한 파일에는 장비명을 입력하거나 명시적으로 `unknown`을 지정해야 한다. 확정 상태는 원격 전송 완료를 의미하지 않는다.

원격 아카이브에 업로드·검증이 끝난 로컬 파일(연결된 XMP가 있다면 XMP 포함)을 선택하면 **로컬 원본 비우기**를 실행할 수 있다. 실행 시 워커가 OMV에 SFTP로 실시간 연결해 원격 파일 존재·크기를 확인한 뒤 `managed`의 로컬 파일만 삭제하고 상태를 **아카이브 보관**으로 전환한다. 썸네일·메타데이터·XMP 정보와 이벤트 배정은 그대로 유지되며, 아카이브 사본이 있는 행의 **다운로드** 링크로 언제든 원본을 다시 받을 수 있다. **아카이브 보관** 상태의 파일은 Source 업로드 목록에서는 제외된다.

**이벤트 수정**에서는 최상위 이벤트의 이름·기간·시간대를, **소분류 수정**에서는 이름을 바꾼다. 기존 파일 배정은 유지된다. 바뀐 이름과 시작일은 Source 폴더와 이후 예약하는 업로드 경로에 반영되지만, 이미 예약된 작업과 원격 폴더의 이름은 바꾸지 않는다. 수정한 기간으로 파일을 추가하려면 **기간으로 모으기**를 실행한다.

**이벤트 삭제**는 하위 소분류도 함께 삭제하고 소속 파일을 미배정으로 돌린다. **소분류 삭제**는 파일을 상위 이벤트의 초안으로 돌린다. 두 동작 모두 확인 대화상자를 거치며 managed의 원본은 유지한다.

### 보관 파일 확대 미리보기와 영상 재생

이벤트 목록(**전체 파일**, **미배정**, 이벤트, 소분류)에서 로컬 보유(`available`) 파일의 썸네일을 누르면 큰 사진 미리보기 또는 브라우저 영상 재생기가 열린다. 배정·확정 여부와 관계없이 열 수 있으며, 썸네일 생성에 실패한 파일이라도 로컬 원본이 있으면 열 수 있다.

- 현재 필터 결과에 표시된 로컬 보유 파일들 사이를 `←` / `→` 키 또는 **이전** / **다음** 버튼으로 이동한다.
- 영상 재생기(`<video>`)에 포커스가 있을 때 `←` / `→`는 브라우저 재생 위치 이동에 사용되며 파일 전환으로 가로채지 않는다.
- `Esc` 키나 닫기 버튼으로 모달을 닫으면 열었던 썸네일로 포커스가 복귀하고, 기존 파일 선택·필터·목록 스크롤 위치가 그대로 유지된다. 이벤트 배정·확정·장비 보정은 모달을 닫은 뒤 기존 하단 분류 도구에서 수행하며, 모달 안에서 managed 파일을 삭제하는 기능은 제공하지 않는다.
- **아카이브 보관(`archived`)** 상태 파일은 **로컬 원본 없음**으로 표시되며 확대 미리보기·영상 재생을 지원하지 않는다. 원격 사본은 행의 **다운로드** 링크로 내려받는다.
- 브라우저 코덱 미지원 등으로 재생·로딩 오류가 나면 **다시 시도** 또는 **원본 열기**(새 탭)를 사용하고, 원본 변경이나 접근 권한 오류가 표시되면 **Incoming Library → 파일 검사**로 다시 확인한다.

## 아카이브 전송

### Source와 Destination 탐색

왼쪽 **Source**는 확정 배치를 `이벤트 → [소분류 →] 장비 → 파일` 구조로 보여 준다. 연결된 XMP는 원본 옆에 별도 파일로 표시되며 개별 선택할 수 있다. 이 트리는 분류를 보여 주는 논리 구조이며 실제 managed 디렉터리 구조와 다르다.

오른쪽 **Destination**에서 **아카이브 연결**을 누르면 설정된 SSH 계정과 저장 절대경로로 원격 목록을 조회한다. 폴더를 눌러 들어가거나 **상위 폴더**로 돌아가고, **새로 고침 / 다시 연결**로 목록을 다시 읽는다. 일반 파일에는 **다운로드** 버튼이 제공되며, 심볼릭 링크는 목록에 표시만 하고 열거나 내려받지 않는다.

연결된 상태에서 Destination 헤더의 **원격 인덱싱**을 누르면 Photo Saver 외부에서 미리 올려둔 기존 사진·영상·XMP까지 원격 아카이브 DB(`remote_files`)에 증분 스캔할 수 있다. 대화상자에서 **전체 아카이브 루트** 또는 **현재 폴더만**을 선택하고, 필요 시 크기·수정 시각이 같은 파일도 전체 해시를 다시 검증하는 옵션을 켤 수 있다. 진행 카드에서 탐색·해시 진행률과 신규 해시·변경 없음·누락 개수를 확인하고 **인덱싱 중지**로 중단할 수 있다. 중단해도 이미 완료된 해시 기록과 기존 인덱스는 유지된다.

### 업로드와 경로 규칙

Source의 파일·폴더를 선택하고 **업로드**를 누르면 현재 Destination 폴더로 전송 작업을 등록한다. Source 항목을 Destination의 빈 영역에 놓으면 현재 폴더에, 특정 폴더 위에 놓으면 그 폴더 아래에 업로드한다. 이미 선택된 항목을 드래그하면 선택 전체를 사용하고, 선택되지 않은 항목을 드래그하면 그 항목을 사용한다. 폴더 선택에는 하위 원본과 XMP가 포함되며, 한 번에 최대 10,000개 파일을 보낼 수 있다.

목적지 아래에는 **현재 Source에서 보이는 상대 구조**가 붙는다. 따라서 Source를 어디까지 열었는지에 따라 경로가 달라진다. 예를 들어 논리 경로가 `260903_제주여행/GoPro/GX010001.MP4`이고 Destination이 아카이브 루트라면 다음과 같다.

| 현재 Source 위치 | 선택 항목 | 아카이브 루트 아래 생성되는 경로 |
| --- | --- | --- |
| Source 루트 | `260903_제주여행` 폴더 | `260903_제주여행/GoPro/GX010001.MP4` |
| `260903_제주여행` 내부 | `GoPro` 폴더 | `GoPro/GX010001.MP4` |
| `260903_제주여행/GoPro` 내부 | `GX010001.MP4` | `GX010001.MP4` |

현재 화면은 업로드 버튼이나 드롭으로 작업을 등록하며, 선택한 파일 중 원격 아카이브의 **다른 경로**에 이미 동일한 파일이 보관되어 있으면 **원격 중복 파일 감지** 대화상자를 열어 기존 원격 경로를 보여 준다. 대화상자에서 **중복 제외하고 신규만 업로드**하거나 **별도 사본으로 모두 업로드**를 선택할 수 있다. 같은 목적지의 동일 내용 파일은 검증 후 건너뛰고(`remote_files`의 크기·수정시각이 그대로이면 즉시 건너뜀), 내용이 다른 동명 파일은 덮어쓰지 않고 실패로 표시한다. Source 또는 Destination 연결 정보가 바뀌면 다시 탐색하거나 연결한 뒤 선택한다.

진행 영역에서 처리 파일 수, 업로드·건너뜀·실패 수, 현재 파일, 전송량과 단계를 확인한다. **업로드 중지**로 중지를 요청할 수 있고, 실패 목록을 펼쳐 경로별 사유를 본다. 완료 후 현재 Destination 목록이 갱신된다. Incoming 작업과 원격 작업은 각각 한 건씩 동시에 진행할 수 있다.

## 파일 기록

**보유 파일**에서는 managed 원본(`보관 중`·`아카이브 보관`·`파일 없음`)·XMP와 Incoming 검사 기록을 경로별로 조회한다. 같은 해시라도 경로가 다르면 별도 기록이며, 파일 상태와 배치 확정 여부, 아카이브 검증 이력 유무를 함께 보여 준다. 현재 저장 절대경로에 검증된 원격 사본이 있으면 **아카이브 다운로드** 또는 **다운로드** 링크로 바로 내려받을 수 있다.

**아카이브 기록**에서는 파일별 작업 번호, SHA-256, 목적지, 검증 결과·시각과 오류를 조회한다. **업로드 검증**, **동일 파일 확인**, **과거 전송 완료**, **실패**, **진행 대기**, **파일별 결과 미기록** 상태를 구분한다. 과거 자료에 루트나 결과가 없으면 미기록으로 표시한다. 검증 표시는 전송 시점의 기록이며 원격 파일의 현재 상태를 실시간 검사한 결과는 아니다.

**원격 인덱스**에서는 원격 아카이브 스냅샷(`remote_files`)에 등록된 모든 파일과 최근 전체 인덱싱 시각을 조회한다. 왼쪽 원격 폴더 트리(최상위·하위 2단계 및 루트 직속 파일)로 경로를 좁히고 **보관 중 / 원격 전용 (카탈로그 미등록) / 누락됨 / XMP** 필터와 파일명·원격 경로·SHA-256 검색을 사용할 수 있다. Photo Saver 외부에서 올려둔 기존 영상도 원격 인덱싱을 마치면 이 탭에서 바로 검색하고 **다운로드**할 수 있으며, Incoming·업로드 중복 차단에도 자동으로 반영된다.

왼쪽 이벤트·소분류·장비 트리(또는 원격 폴더 트리)로 범위를 좁히고, 파일명·경로·SHA-256을 입력해 **검색**한다. 필터를 바꾼 뒤 **검색**해야 적용된다. 한 페이지는 기본 50개이며 이전·다음 페이지와 SHA-256 **복사** 버튼을 제공한다.

## 설정

### 촬영도구 이름

**촬영도구 이름**에서 메타데이터로 감지한 원래 이름과 적용할 이름을 확인한다. 원하는 이름을 입력하고 **이름 저장**을 누르면 기존 파일과 이후 같은 장비명으로 들어오는 파일에 적용된다. 공백은 자동으로 변환하지 않는다. 제조사·모델명이 같은 장비는 하나의 촬영도구로 취급하며, 파일별로 직접 지정한 이름은 유지한다.

이름은 이벤트 목록·필터·아카이브 Source·파일 기록과 이후 업로드 경로에 적용된다. 배정·확정 상태와 실제 로컬 원본 경로는 유지한다. 기존 원격 폴더와 전송 당시 경로는 바꾸지 않는다. 다른 촬영도구나 관련 이벤트 소분류와 폴더명이 충돌하면 다른 이름을 입력해야 한다. 업로드 대기·실행 중에는 이름을 변경할 수 없다. 이름 규칙은 카탈로그 백업에 포함된다.

### 스토리지 연결

1. **IP 등록 / IP 변경**에서 IPv4 또는 IPv6 주소를 저장한다. 호스트 이름 입력은 지원하지 않는다.
2. **경로 등록 / 경로 변경**에서 원격 저장 절대경로를 입력한다.
3. SSH 계정명은 `.env`의 `PHOTO_SAVER_STORAGE_USER`로 설정한다. 화면에서는 등록 여부만 표시하며 수정하지 않는다.
4. **공개키 생성** 후 **공개키 복사**로 키를 복사해 원격 SSH 계정에 등록한다. 복사는 키마다 한 번만 가능하며, **공개키 재생성**은 확인 후 기존 키를 교체하므로 새 키를 원격에 다시 등록해야 한다.
5. **접속 테스트**를 실행한다. 해당 IP에 저장된 호스트 키가 없을 때 지문 확인 대화상자가 열린다. 서버에서 확인한 지문과 비교한 뒤 **지문 확인 및 접속**을 실행한다. 저장된 키와 서버 키가 다르면 접속을 거부하며, 서버 재설치 등으로 키가 바뀐 경우 **호스트 키 초기화**를 실행한 뒤 다시 접속 테스트로 신뢰할 수 있다.

클립보드 복사에는 브라우저의 클립보드 권한이 필요하다. 키·호스트 확인과 실제 전송의 세부 규칙은 [아카이브·스토리지 문서](archive-and-storage.md)를 참고한다.

### DB 백업과 복원

**DB 백업 다운로드**는 이벤트와 파일 배치가 포함된 SQLite 카탈로그를 내려받는다. 사진·영상과 SSH 설정을 묶어 내려받는 기능은 아니다.

**백업 파일 선택 → 복원**에서 SQLite 파일을 선택하고 확인하면 현재 카탈로그 내용을 교체한다. 원본 파일은 디스크에 남는다. 진행 중인 파일 작업이 있으면 백업·복원 버튼이 비활성화된다.

### 데이터 초기화

초기화는 **설정 → 데이터 초기화** 한 가지다. 확인창에서 **모든 데이터 삭제**를 정확히 입력하고 실행한다. 기존의 기록만 비우기와 managed 되돌리기는 제거했다.

워커는 `managed`의 사진·영상 원본과 XMP·THM·LRV·숨김 파일, 썸네일과 서버 임시 데이터를 영구 삭제한다. 이어 파일 목록·이벤트·배정·장비/시각 보정·이름 규칙·전송·검증·작업 기록을 모두 비운다. 초기화 작업 자신의 기록도 남기지 않는다. 파일을 다른 폴더로 이동하거나 해시를 계산하지 않는다.

**incoming 디렉터리와 모든 파일·하위 폴더(이전 returned 폴더 포함), SSH 연결 설정·키·호스트 키와 원격 아카이브는 유지한다.** 앱 코드·실행 설정과 저장 영역의 루트 디렉터리도 유지한다. 초기화 중에는 새 파일을 복사하지 않는다. 다른 작업이 진행 중이면 시작할 수 없고, 초기화 중의 변경 요청은 서버가 거부한다.

삭제한 파일은 복구할 수 없다. DB 백업에는 원본 파일이 포함되지 않는다. 중간 실패 시 일부 파일은 이미 삭제되었을 수 있으며 되돌리지 않는다. 오류를 해결한 뒤 같은 초기화를 다시 실행한다. 워커가 중단되면 재시작 시 남은 항목을 계속 삭제한다. 성공 후 **파일 검사**로 보존한 Incoming 파일을 다시 수집할 수 있다. managed에만 있던 원본은 삭제되므로 다시 나타나지 않는다.

## 화면 갱신과 작은 화면

파일 작업 중에는 상태를 반복 조회하고, API 연결 오류가 나면 다시 연결을 시도한다. Incoming에서 파일시스템 변경을 반영하려면 **파일 검사**를 사용한다. 파일 기록과 Destination의 **새로 고침**은 각각 기록과 원격 목록을 다시 읽는다.

좁은 화면에서는 사이드바가 위쪽 메뉴로 바뀌고 이벤트·아카이브 영역이 세로로 배치된다. 넓은 표는 가로 스크롤로 확인할 수 있다. 프론트엔드는 [HTML](../frontend/index.html), [JavaScript](../frontend/app.js), [CSS](../frontend/styles.css)만으로 구성된다.
