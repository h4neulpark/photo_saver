# 화면별 사용 안내

## 원격 OMV 서버 끄기

아카이브 또는 설정에서 **OMV 끄기**를 누르고 종료 확인창을 읽은 뒤 확인하세요. 이 작업은 Home Assistant 종료 스크립트를 실행하며 아카이브 연결과 진행 중인 다운로드가 끊길 수 있습니다. 취소 버튼에 기본 포커스가 놓입니다. 부팅 중·미확인 상태이면 먼저 **상태 확인**을 누르세요. 종료 설정이 없거나 원격 파일 작업이 진행 중이면 버튼이 비활성화됩니다.

종료 요청, SSH 서비스 중단, HA 전원 꺼짐의 세 단계를 확인합니다. **대기 중지**는 확인만 중단하며 이미 보낸 종료 요청은 취소되지 않습니다. **SSH 응답 중단, HA 미확인** 결과면 서버 상태를 직접 확인하세요. 작업 내역과 설정의 최근 종료 기록에서 센서·SSH·요청 결과를 볼 수 있습니다. 위험 작업은 기록의 원클릭 재실행 대신 **아카이브에서 상태 확인**으로 돌아갑니다.

응답이 유실되면 브라우저가 같은 요청 ID를 보존하며 자동 재전송하지 않습니다. **같은 요청 다시 확인**은 확인창을 거쳐 같은 ID로 재접수합니다. 정상 종료 확인 후에는 아카이브 목록과 선택이 자동 정리됩니다. [운영 설정](setup-and-operations.md#omv-원격-종료-선택-설정)은 운영자가 적용합니다.

## 원격 OMV 서버 켜기

아카이브 전송 화면에서 **아카이브 연결** 옆 **OMV 켜기**, 또는 설정 → 스토리지 연결 → **OMV 원격 시작**의 같은 버튼을 누르세요. Home Assistant 설정은 서버 운영자가 먼저 등록해야 하며 SSH 설정이 없어도 시작 요청은 가능합니다. 버튼이 비활성화되면 설정 안내 또는 진행 중인 원격 작업을 확인하세요. 로컬 검사는 함께 진행할 수 있습니다.

**켜기 요청 / 서버 응답 / 아카이브 접근**은 각각 다른 사실입니다. HA 요청 접수만으로 서버가 켜졌거나 전송 준비가 끝났다고 보지 마세요. **서버 응답 보고 · SSH 설정 필요** 결과면 스토리지 설정을 완료하세요. 인증·호스트 키·폴더·권한 안내는 해당 설정을 확인하세요. **처리 여부 알 수 없음**이면 이미 기동 요청이 전달되었을 수 있으므로 서버 상태를 먼저 확인하세요.

기본 대기 시간은 접수부터 최대 180초입니다. **대기 중지**로 기다리기를 멈출 수 있지만 이미 보낸 켜기 요청은 취소되지 않습니다. 새로고침·다른 화면 이동은 요청을 다시 보내지 않고 기존 상태만 확인합니다. 응답이 유실되면 같은 요청 ID로 확인하며, **같은 요청 다시 확인**은 사용자가 명시적으로 누르는 재접수입니다. 새 작업을 시작하려면 기존 작업 종료 결과를 확인하세요. 서버가 준비되면 현재 대상의 아카이브 목록을 갱신하며 **파일 업로드는 따로 시작**합니다.

## Mac·iPad·iPhone에서 Incoming으로 업로드

**기기에서 업로드 → 사진·파일 선택**에서 사진 보관함·파일 앱·Finder 파일을 여러 개 고른다. 저장할 하위 폴더는 선택 사항이며 Mac에서는 폴더를 드롭하여 내부 구조를 유지할 수도 있다. 폴더는 6단계·180자 이내, 한 번에 최대 2,000개 파일을 처리한다. 숨김 드롭 항목은 제외한다.

iPhone·iPad 사진 보관함에서 원본 화질(HEIC·MOV)을 유지하려면 선택 화면 ‘옵션’에서 ‘현재 항목’을 선택하세요.

JPG·JPEG·PNG·WEBP·HEIC·HEIF·MP4·MOV와 동반 XMP·THM·LRV·AAE를 지원한다. DNG 등 미지원 형식과 빈 파일은 결과에 제외 이유를 남기고 나머지를 계속 처리한다. 사진 → 영상 → 동반 파일 순으로 업로드하며 기존 파일과 이름이 겹치면 (1) 등 번호를 붙인다. 같은 배치의 원본 개명에 맞춰 동반 파일 이름도 조정하되 원본 stem이 여러 개인 경우 단순 stem 리매핑은 생략한다.

패널과 상단 알약에서 진행률을 확인하고 **중지**를 누르면 현재 임시 업로드와 대기 파일을 취소한다. 이미 완료한 파일은 보존한다. 일시적 청크 통신 오류는 서버 오프셋을 확인해 최대 두 번 재시도한다. 전송 중에는 탭을 열어 두고 기기 절전/앱 전환을 피한다. 화면 잠금 방지는 브라우저가 허용하는 경우에만 적용되며 새로고침 뒤 자동 재개는 제공하지 않는다.

기본으로 **완료 후 파일 검사**가 켜져 있다. 성공한 파일이 있으면 로컬 작업이 비었을 때 검사를 시작하고 로컬 작업 진행 중이면 끝난 뒤 **파일 검사**를 누르라는 안내를 표시한다. 원격 전송과 기기 업로드는 함께 실행할 수 있고 데이터 초기화 중에는 새 업로드가 차단된다. 패널은 화면 갱신 중 파일 입력·폴더 포커스와 결과 펼침 상태를 유지한다.


이 문서는 현재 [프론트엔드](../frontend/app.js)와 [API](../backend/api.py)에 구현된 화면 동작을 설명한다. 실행 후 기본 주소인 `http://127.0.0.1:8888`에서 접속한다.

## 페이지와 기본 흐름

| 메뉴 | URL 해시 | 용도 |
| --- | --- | --- |
| 가져오기 | `/#incoming` | 로컬 파일 검사, 이동, 사진 삭제, XMP 연결 |
| 이벤트 분류 | `/#events` | 보관 파일의 이벤트 배정, 장비·시각 보정, 분류 확정 |
| 아카이브 전송 | `/#archive` | 분류 확정된 파일과 원격 폴더 탐색, 업로드 |
| 파일 기록 | `/#catalog` | 파일 해시와 전송 검증 이력 조회 |
| 작업 내역 | `/#jobs` | 서버 작업과 이 브라우저의 기기 업로드 이력·진행 상태 |
| 설정 | `/#settings` | SSH 연결 정보, 키, 카탈로그 백업·복원 |

처음 접속하거나 알 수 없는 해시를 사용하면 가져오기가 열린다. 일반적인 사용 순서는 **incoming에 파일 복사 → 검사 → 보관함으로 가져오기 → 이벤트 배정·확정 → 아카이브 연결·업로드 → 파일 기록 확인**이다. 원격 스토리지 연결 없이도 로컬 검사와 이벤트 분류를 진행할 수 있다.

사이드바는 **작업 흐름**의 1 가져오기 → 2 이벤트 분류 → 3 아카이브 전송과 **조회·관리**의 파일 기록·작업 내역·설정으로 나뉜다. 숫자 배지는 가져오기의 대기 항목(이동 가능·중복·확인 필요와 연결 대기 XMP), 이벤트의 미배정 파일, 아카이브의 전송 대기 확정 로컬 파일을 각각 보여 준다. 원본 전송이 끝났어도 XMP가 미전송이면 아카이브 대기에 포함한다. 작업 내역 배지는 활성 서버 작업과 기기 업로드의 합계다. 0건은 숨기고 100건 이상은 **99+**로 줄이며 마우스를 올리거나 보조기술을 사용하면 정확한 수치를 확인한다.

## 결과 배너와 작업 내역

Incoming 처리 결과는 검사 진행 표시 바로 아래, 이벤트 분류·아카이브 전송 결과는 화면 상단의 작은 배너에서 확인한다. 정상 완료는 접힌 상세, 확인 필요·중지는 펼친 상세, 실패는 빨간 오류 배너로 표시한다. 상세를 직접 접거나 펼친 상태는 화면 갱신 중 유지된다. **닫기**는 결과 표시만 숨기며 **작업 내역**에서는 계속 볼 수 있다. 진행 중인 작업에는 닫기 버튼이 없다. 기기 업로드 결과의 닫기는 완료 요약과 진행 수치를 정리한다.

**작업 내역**에서 전체·진행 중·실패·확인 필요·완료를 고르고 작업 영역으로 목록을 좁힌다. 완료 필터에는 일부 파일의 확인이 필요한 완료 작업도 포함된다. 상단 필터 건수는 전체 기록 기준이며 **이전 기록 더 보기**로 오래된 서버 작업을 추가한다. 작업별로 Incoming·미배정·이벤트 분류·아카이브 기록·원격 인덱스를 열고, 확인 필요 로컬 작업에서는 다시 검사할 수 있다. 업로드·원격 인덱싱·기기 업로드는 진행 중 중지할 수 있다. 내비게이션의 숫자와 상단 작업 표시에서 실행 중인 작업 수를 확인한다.

기기 업로드는 **이 브라우저 기록** 배지가 붙는다. 서버 기록과 달리 현재 브라우저의 로컬 저장소에 최근 20개 배치만 저장하므로 다른 기기와 공유되지 않는다. 배치별 파일 목록은 실패·제외·이름 변경·취소를 우선하여 최대 100개를 보관한다. 서버 결과도 상세 목록이 최대 100개이며 잘린 경우 전체·표시 건수 안내를 확인할 수 있다. 저장소를 사용할 수 없으면 현재 탭의 메모리에서 기록과 닫기 상태를 유지한다. 서버 데이터 초기화 시 이 브라우저 기록과 닫기 상태를 지우며 카탈로그 복원 성공 시 닫기 상태도 지운다.

이벤트 분류에서는 파일을 선택한 뒤 하단의 **선택 N개 분류 확정** 버튼으로 확정한다. 파일 선택이 없으면 선택 도구가 숨겨지고, 1개 이상 선택하면 하단에 **선택 해제**, 이동·정보 수정·분류 확정 작업이 나타난다. 데스크톱·태블릿에서도 선택 도구는 스크롤 중 화면 하단에 붙는다. NAS 검증 대상에만 **NAS 보관 후 로컬 비우기**를 표시하며 일부만 해당하면 대상 수를 붙인다. **분류 확정**이 유일한 주 작업 버튼이다. 상단의 **기간으로 모으기**는 최상위 이벤트에만 표시한다. 왼쪽 **이벤트** 패널의 **+ 생성** 버튼은 이벤트가 없을 때 강조하고, 이미 있으면 보조 버튼으로 표시한다.

파일 기록의 **보유 파일 / 원격 인덱스** 탭에는 전체 건수가 표시된다. 탭에 포커스한 상태에서 좌우 화살표·Home·End로 전환할 수 있다. 영역 필터는 선택 즉시 반영하고 검색은 입력 후 280ms에 반영하며 한글 조합 중에는 기다린다. Enter로 즉시 검색하거나 **필터 초기화**로 조건을 지울 수 있다. 검색 결과를 불러오는 동안 기존 표를 유지한다.

## 가져오기

### 가져오기 탭

**파일 목록 / XMP 연결 / 동반 파일 확인** 탭에서 작업을 나눈다. 각 탭의 숫자는 검사 항목, XMP 파일, 확인할 동반 파일 수다. 탭에 포커스한 뒤 좌우 화살표·Home·End로 전환할 수 있다. 탭을 오가도 파일 썸네일·스크롤·선택과 기기 업로드 입력을 유지한다. 보조 탭이 0건이 되어도 현재 탭에 머물며 **파일 목록으로 돌아가기**를 제공한다. 완료한 검사 줄은 시간과 총 검사 수, 보조 확인 건수만 보여 주고 검사 중에는 단계·진행률·현재 경로를 표시한다.

### 검사와 파일 선택

1. 운영체제에서 사진·영상을 incoming에 넣거나 **기기에서 업로드**를 사용한다.
2. **파일 검사**를 누른다. 화면에서 기존 보관 파일 확인, Incoming 해시 검사, 썸네일 생성 등 현재 처리 단계를 본다. 결과에는 Incoming 기준 경로, 수정 일시, 크기, 썸네일과 결과 사유가 표시된다.
3. **전체 / 이동 가능 / 중복 / 확인 필요**로 결과를 좁히고 **모든 형식 / 사진 / 영상**을 선택한다. 검색은 파일명, 폴더와 XMP의 제목·설명·키워드·장소·GPS·기록 시각을 대상으로 한다.
4. 이동할 신규 항목을 선택하고 **보관함으로 가져오기 (N)**을 누른다. 이동은 선택에서 **이동 가능**인 파일에 적용한다.

선택이 없으면 작업 안내만 표시한다. 파일을 선택하면 **보관함으로 가져오기 (N)**, **중복 정리 (M)**, **사진 삭제 (K)** 중 적용 가능한 작업만 나타난다. 중복만 선택하면 중복 정리가 강조된다. 영상은 사진 삭제 대상에 포함하지 않는다. **선택 해제**로 안내 상태로 돌아간다.

**이동 가능**과 **중복**인 사진·영상에 선택 상자가 있다. **모두 선택**과 일괄 작업은 현재 상태·형식·검색 조건에 표시된 선택 가능 항목에 적용된다. 필터나 검색으로 숨겨진 파일은 선택에서 빠진다.

**표 보기 / 카드 보기**를 전환할 수 있으며, 이 보기 설정은 브라우저의 로컬 저장소에 보관한다. 새로 추가하거나 변경한 파일은 다시 **파일 검사**로 확인한다. 최근 작업 결과에서 이동·정리·보류 상태를 확인하고, 이동한 파일은 **이벤트 분류 → 미배정**에서 이어서 분류한다.

### 중복 정리

**중복**인 사진 또는 영상을 선택하고 **중복 정리**를 누른다. 같은 SHA-256 그룹의 정리할 경로·용량과 남길 사본 후보를 확인한다. 후보가 여러 개면 사용할 사본을 고른다. 같은 Incoming 그룹의 파일을 남기기로 하면 해당 파일은 정리 목록에서 빠진다.

워커가 Incoming 파일과 남길 사본의 내용을 확인한 뒤 정리 대상으로 승인한 Incoming 미디어를 영구 삭제한다. 함께 삭제 옵션이 켜지면 짝이 확인된 보조 파일도 정리한다. OMV 사본을 고르면 현재 설정된 아카이브에서 실제 파일의 SHA-256을 대조한다. 파일이 변경됐거나 사본을 확인할 수 없는 경우는 **확인 필요**로 남는다. 확인창에서 XMP·THM·LRV·AAE의 삭제·보존 상태를 확인할 수 있다. XMP는 별도 XMP 연결 과정에서 처리할 수 있다.

### 원본 미리보기와 사진 삭제

썸네일을 누르면 큰 미리보기가 열린다. 사진은 이미지로, 영상은 브라우저 재생기로 표시하며 **원본 열기**는 새 탭에서 파일을 연다. 미리보기에서 경로와 중복 근거를 확인하고 현재 파일을 선택하거나 해제할 수 있다. HEIC·HEIF 미리보기는 JPEG로 변환하고, 영상 재생 가능 여부는 브라우저 코덱 지원에 따른다. 검사 후 파일이 변경되거나 이동되면 **파일 검사**로 상태를 다시 확인한다.

| 위치 | 키 | 동작 |
| --- | --- | --- |
| 카드의 썸네일에 포커스 | 방향키 | 카드 간 포커스 이동 |
| 카드의 썸네일에 포커스 | `Enter` | 미리보기 열기 |
| 카드 또는 미리보기 | `Delete` / `Backspace` | 삭제 가능한 사진의 삭제 확인 열기 |
| 미리보기 | `←` / `→` | 현재 필터의 미리보기 가능한 이전·다음 파일 표시 |
| 삭제 확인 | `Enter` | 포커스된 버튼 실행. 확인을 열면 취소에 포커스 |
| 미리보기 삭제 확인 | `Esc` | 삭제 확인 취소 |
| 미리보기 | `Esc` | 미리보기 닫기 |

영상 재생기에 포커스가 있을 때 좌우 방향키는 재생 위치를 제어한다. **이동 가능** 상태의 불필요한 사진은 **사진 삭제**로 Incoming에서 영구 삭제할 수 있다. 중복 사진은 **중복 정리**를 사용한다. 목록에서 여러 사진을 선택하면 대상 경로를 확인하는 대화상자가 열린다. 미리보기에서 한 장씩 삭제하면 삭제 후 다음 파일로 이동하고, 남은 파일이 없으면 미리보기가 닫힌다.

### XMP 연결

검사에서 함께 발견한 XMP와 THM·LRV·AAE는 해당 원본에 처리 상태와 함께 표시된다. 이동 가능한 원본에 연결된 XMP도 함께 보관하며, 짝이 확실한 THM·LRV·AAE는 원본 이동 후 정리한다. 중복 정리 창에서는 **짝이 확인된 카메라 보조 파일 함께 삭제**가 기본으로 켜진다. 파일별 삭제·보존 표시와 용량을 확인하고 필요하면 옵션을 끈다. 남길 사본을 바꾸면 보조 파일 목록과 용량도 즉시 갱신된다. XMP와 연결이 불확실한 보조 파일은 항상 보존한다.

### Incoming 보조 파일 일괄 정리

**동반 파일 확인** 탭은 고아 파일, 연결된 원본의 잔여 파일, 보존되는 XMP를 보여 준다. THM·LRV·AAE의 **Incoming 남음**은 파일이 아직 Incoming에 있다는 뜻이며, XMP의 **보존 필요**와 구분한다. **THM·LRV·AAE 일괄 정리**를 누르면 실시간 목록을 불러온다. 빈 탭의 **Incoming 보조 파일 확인**으로도 새 파일을 확인할 수 있다.

고아와 중복 원본의 보조 파일만 기본 선택된다. 이동 대기 원본은 이동 시 자동 정리 예정이므로 기본 선택하지 않는다. 분류별 체크, **고아·중복만 선택**, **전체 선택**, **선택 해제**로 선택하고 용량을 확인한다. 읽기 불가는 선택할 수 없다. 원본 보관 여부를 확인할 수 없는 고아 파일에는 주의 안내가 표시되며, LRV에는 저화질 영상이 남아 있을 수 있다. **선택한 N개 영구 삭제**는 선택한 THM·LRV·AAE만 삭제한다. XMP와 원본 사진·영상은 유지된다.

결과의 **파일 없음**은 이미 사라진 항목이며 오류가 아니다. **확인 필요**는 변경되거나 읽지 못한 파일을 보존했다는 뜻이다. 상태 변경 오류가 나오면 창을 닫고 목록을 다시 확인한다. 같은 시간에 로컬 작업은 하나만 실행되며 원격 작업은 함께 실행할 수 있다. 중복·사진 삭제 후 보조 파일이 남았다면 결과의 **동반 파일 확인**으로 이동한다. 상세 연결 규칙은 [수집·분석 문서](media-pipeline.md)를 참고한다.

이미 managed에 원본이 있는 XMP 후보는 **XMP 연결** 탭의 표에 나타난다. 기록된 시각과 원본 후보를 확인하고 **선택한 XMP 연결**을 실행한다. 같은 원본에 여러 XMP를 선택하면 실행 버튼이 비활성화된다. 연결할 수 없는 파일은 사유를 확인한다.

## 이벤트 분류

파일 목록 오른쪽의 표·격자 아이콘(**표 보기 / 카드 보기**)으로 전환한다. 아이콘에 마우스를 올리면 이름이 표시되고, 보기 방식은 브라우저에 저장된다. 카드 보기의 **전체 선택**은 보기 아이콘 옆에, 표 보기의 전체 선택 체크박스는 표 머리글에 표시된다. 보기 방식을 바꿔도 선택은 유지된다. 카드에는 썸네일, 촬영 시각, 장비, 분류 상태가 표시되며 **XMP**를 누르면 관련 정보를 확인한다. 촬영 시각을 누르면 해당 파일의 장비·시각을 수정할 수 있다. **아카이브 보관** 파일은 썸네일을 유지하지만 로컬 미리보기와 개별 시각 수정은 제공하지 않으며, 다운로드 링크로 원본을 받을 수 있다. 방향키로 카드의 미리보기 버튼 사이를 이동할 수 있다.

목록 위 **전체 / 초안 / 분류 확정 / 아카이브 보관** 상태 칩은 현재 이벤트의 파일 수와 진행 막대를 보여 주며, 누르면 해당 상태로 필터링한다. 선택한 상태 칩을 다시 누르거나 **전체**를 누르면 상태 필터가 해제된다. 초안·분류 확정은 로컬 파일을, 아카이브 보관은 로컬 원본을 비운 파일을 집계하므로 세 상태의 합은 전체와 같다. **NAS 사본 보유**는 로컬 원본과 아카이브 사본을 함께 가진 파일 수다. 검색·장비·촬영일 필터의 표시 파일 수와 별개로 요약은 현재 이벤트 전체를 기준으로 유지된다. 조건에 맞는 파일이 없으면 **필터 초기화**로 모든 필터와 검색어를 한 번에 해제할 수 있다.

파일을 선택하면 목록 하단에 이동·정보 수정·분류 확정 도구가 나타난다. 데스크톱과 태블릿에서도 선택 도구는 스크롤 중 화면 하단에 붙어 있고, 선택을 모두 해제하면 숨겨진다. 왼쪽 이벤트 목록은 넓은 화면에서 상단에 붙어 있으며 긴 목록은 그 안에서 스크롤한다.

### 생성과 기간 배정

왼쪽 목록의 **전체 파일**은 managed의 사용 가능한 파일 전체를, **미배정**은 이벤트에 속하지 않은 파일을 보여 준다. 최상위 이벤트의 파일 수에는 소분류 파일도 포함하지만, 해당 이벤트를 눌렀을 때 오른쪽 목록에는 직접 배정된 파일만 표시한다.

왼쪽 **이벤트** 패널의 **+ 생성**을 눌러 이름, 시작일, 종료일, 촬영일 기준 시간대를 지정한다. 이벤트가 없으면 같은 패널에 첫 이벤트 생성 안내가 표시된다. **생성하고 파일 모으기**를 누르면 시각이 확인된 미배정 파일 중 기간에 맞는 파일을 자동으로 배정한다. 시작일과 종료일을 모두 포함하며, 여러 최상위 이벤트 기간에 겹치거나 촬영 시각 확인이 필요한 파일은 미배정에 남는다. 이후 오른쪽 이벤트 제목 옆 **기간으로 모으기**를 다시 실행할 수 있다. 이 버튼은 최상위 이벤트에서만 표시된다.

최상위 이벤트의 폴더명에는 `YYMMDD_` 시작일이 붙는다. 이름이 같은 날짜 접두사로 시작하면 한 번만 붙인다. 예를 들어 시작일이 `2026-09-03`인 `제주여행`은 `260903_제주여행`으로 표시된다.

시간대 선택 목록은 앱 기본 시간대와 `Asia/Seoul`, `Asia/Tokyo`, `Asia/Singapore`, `Europe/Paris`, `America/Los_Angeles`, `UTC`로 구성된다. 저장된 이벤트의 기존 시간대도 목록에 유지된다.

### 수동 배정, 소분류, 정보 보정

- 제목 옆 **⋯** 메뉴의 **소분류 추가**는 최상위 이벤트 아래 한 단계만 지원한다. 소분류는 이름만 입력하며 기간과 시간대는 부모 이벤트를 기준으로 표시한다.
- 파일을 선택하고 하단 **이동할 이벤트**에서 목적지를 골라 **이동**한다. 미배정 파일의 최초 배정, 다른 이벤트 이동, 소분류 분배, 부모 이벤트로 되돌리기에 같은 동작을 사용한다. 실제 managed 파일 경로를 옮기지 않고 배정만 변경하며, 다른 이벤트로 이동한 파일은 초안이 된다.
- 검색은 파일명·장비·XMP 정보를 대상으로 하고, 상태 칩·장비·촬영일 필터를 함께 사용할 수 있다. 장비 필터에서 **장비 확인 필요**를 선택하면 장비명이 없는 사진·영상만 표시한다. 직접 `unknown` 등으로 지정한 파일은 해당 장비로 분류되므로 이 항목에서 제외한다. 전체 파일·미배정·이벤트·소분류에서 동일하게 사용할 수 있고, 필터를 바꾸면 기존 선택을 해제한다. 촬영일은 선택한 이벤트 또는 부모 이벤트의 시간대를 따른다.
- **장비·촬영 시각 수정**으로 여러 파일을 한 번에 보정한다. **촬영 장비**에서 전체 보관 파일에 사용 중인 장비명을 선택하거나 **직접 입력**으로 새 이름을 지정한다. 촬영 시각의 기본값은 **변경하지 않음**이므로 장비만 배정할 수 있다. 직접 시각을 입력하거나 EXIF·영상 메타데이터, XMP, 파일 수정 시각을 선택할 수도 있다.
- **XMP 시각 사용**은 선택 파일 중 사용할 수 있는 XMP 시각이 하나 이상 있으면 활성화된다. 적용 가능 개수와 파일별 XMP 시각·출처를 미리 보여 준다. XMP가 없거나 촬영 시각이 없는 파일은 기존 시각을 유지한다. 장비와 함께 적용하면 장비는 선택한 전체 파일에, XMP 시각은 사용할 수 있는 파일에 각각 적용한다. 완료 메시지에 시각 적용·유지 개수를 표시한다. EXIF·영상 메타데이터와 수정 시각 출처는 기존처럼 모든 선택 파일에 값이 있어야 한다. 연결된 XMP를 외부에서 수정했으면 **가져오기 → 파일 검사**로 다시 읽은 뒤 적용한다.
- 시간대 없는 메타데이터에는 선택한 시간대를 적용한다. 여러 파일에 메타데이터 또는 수정 시각을 적용하면 각 파일의 고유 시각을 사용하며, 직접 입력한 시각은 선택 파일 모두에 동일하게 적용된다.
- 촬영 시각 확인이 필요한 행의 **촬영 시각 지정**으로 출처를 선택한다. XMP가 있으면 **XMP 정보**에서 제목, 설명, 시각, 키워드, 장소, GPS와 분석 상태를 확인한다.

장비를 수정하면 해당 파일의 분류 확정이 해제된다. 시각을 보정해도 기존 이벤트 배정은 유지되며, 다른 이벤트로 자동 재배정되지 않는다.

### 분류 확정과 이벤트 수정·삭제

이벤트에 배정한 로컬 파일을 선택하고 **선택 분류 확정**을 누른다. 대화상자의 이벤트·장비·파일 경로를 확인한 뒤 확정하면 아카이브 전송의 보낼 항목 (로컬)에 표시된다. 장비를 찾지 못한 파일에는 장비명을 입력하거나 명시적으로 `unknown`을 지정해야 한다. 확정 상태는 원격 전송 완료를 의미하지 않는다.

원격 아카이브에 업로드·검증이 끝난 로컬 파일(연결된 XMP가 있다면 XMP 포함)을 선택하면 **NAS 보관 후 로컬 비우기**를 실행할 수 있다. 실행 시 워커가 OMV에 SFTP로 실시간 연결해 원격 파일 존재·크기를 확인한 뒤 `managed`의 로컬 파일만 삭제하고 상태를 **아카이브 보관**으로 전환한다. 썸네일·메타데이터·XMP 정보와 이벤트 배정은 그대로 유지되며, 아카이브 사본이 있는 행의 **다운로드** 링크로 언제든 원본을 다시 받을 수 있다. **아카이브 보관** 상태의 파일은 보낼 항목 (로컬) 업로드 목록에서는 제외된다.

제목 옆 **⋯** 메뉴에서 **이벤트 수정** 또는 **소분류 수정**과 삭제 작업을 연다. 전체 파일·미배정에는 이 메뉴가 없다. 메뉴 버튼에서 위·아래 방향키로 열고 항목 사이를 이동하며, `Home`·`End`로 처음·끝 항목으로 이동한다. `Esc`로 닫으면 메뉴 버튼으로 포커스가 돌아오며, `Tab` 또는 메뉴 바깥 클릭으로도 닫힌다.

**이벤트 수정**에서는 최상위 이벤트의 이름·기간·시간대를, **소분류 수정**에서는 이름을 바꾼다. 기존 파일 배정은 유지된다. 바뀐 이름과 시작일은 보낼 항목 (로컬) 폴더와 이후 예약하는 업로드 경로에 반영되지만, 이미 예약된 작업과 원격 폴더의 이름은 바꾸지 않는다. 수정한 기간으로 파일을 추가하려면 **기간으로 모으기**를 실행한다.

**이벤트 삭제**는 하위 소분류도 함께 삭제하고 소속 파일을 미배정으로 돌린다. **소분류 삭제**는 파일을 상위 이벤트의 초안으로 돌린다. 두 동작 모두 확인 대화상자를 거치며 managed의 원본은 유지한다.

### 보관 파일 확대 미리보기와 영상 재생

이벤트 목록(**전체 파일**, **미배정**, 이벤트, 소분류)에서 로컬 보유(`available`) 파일의 썸네일을 누르면 큰 사진 미리보기 또는 브라우저 영상 재생기가 열린다. 배정·확정 여부와 관계없이 열 수 있으며, 썸네일 생성에 실패한 파일이라도 로컬 원본이 있으면 열 수 있다.

- 현재 필터 결과에 표시된 로컬 보유 파일들 사이를 `←` / `→` 키 또는 **이전** / **다음** 버튼으로 이동한다.
- 영상 재생기(`<video>`)에 포커스가 있을 때 `←` / `→`는 브라우저 재생 위치 이동에 사용되며 파일 전환으로 가로채지 않는다.
- `Esc` 키나 닫기 버튼으로 모달을 닫으면 열었던 썸네일로 포커스가 복귀하고, 기존 파일 선택·필터·목록 스크롤 위치가 그대로 유지된다. 이벤트 배정·확정·장비 보정은 모달을 닫은 뒤 기존 하단 분류 도구에서 수행하며, 모달 안에서 managed 파일을 삭제하는 기능은 제공하지 않는다.
- **아카이브 보관(`archived`)** 상태 파일은 **로컬 원본 없음**으로 표시되며 확대 미리보기·영상 재생을 지원하지 않는다. 원격 사본은 행의 **다운로드** 링크로 내려받는다.
- 브라우저 코덱 미지원 등으로 재생·로딩 오류가 나면 **다시 시도** 또는 **원본 열기**(새 탭)를 사용하고, 원본 변경이나 접근 권한 오류가 표시되면 **가져오기 → 파일 검사**로 다시 확인한다.

## 아카이브 전송

### 보낼 항목 (로컬)과 원격 아카이브 (NAS) 탐색

왼쪽 **보낼 항목 (로컬)**은 분류 확정된 파일을 `이벤트 → [소분류 →] 장비 → 파일` 구조로 보여 준다. 연결된 XMP는 원본 옆에 별도 파일로 표시되며 개별 선택할 수 있다. 이 트리는 분류를 보여 주는 논리 구조이며 실제 managed 디렉터리 구조와 다르다.

오른쪽 **원격 아카이브 (NAS)**는 IP·저장 경로·계정·SSH 키·호스트 신뢰가 모두 설정되어 있으면 첫 진입 때 한 번 자동 연결한다. 미설정이면 설정 링크를 보여 주며 원격 조회를 하지 않는다. 실패하면 **다시 연결**로 수동 재시도할 수 있다. 다른 페이지를 다녀와도 연결과 현재 원격 폴더를 유지한다. IP·저장 경로·키·호스트 신뢰를 바꾸거나 접속 테스트에 성공하면 이전 연결을 비우고 다음 방문 때 새 설정으로 연결한다. **아카이브 연결**로 수동 조회할 수도 있다. 폴더를 눌러 들어가거나 **상위 폴더**로 돌아가고, **새로 고침 / 다시 연결**로 목록을 다시 읽는다. 일반 파일에는 **다운로드** 버튼이 제공되며, 심볼릭 링크는 목록에 표시만 하고 열거나 내려받지 않는다.

연결된 상태에서 원격 아카이브 (NAS) 헤더의 **원격 인덱싱**을 누르면 Photo Saver 외부에서 미리 올려둔 기존 사진·영상·XMP까지 원격 아카이브 DB(`remote_files`)에 증분 스캔할 수 있다. 대화상자에서 **전체 아카이브 루트** 또는 **현재 폴더만**을 선택하고, 필요 시 크기·수정 시각이 같은 파일도 전체 해시를 다시 검증하는 옵션을 켤 수 있다. 진행 카드에서 탐색·해시 진행률과 신규 해시·변경 없음·누락 개수를 확인하고 **인덱싱 중지**로 중단할 수 있다. 중단해도 이미 완료된 해시 기록과 기존 인덱스는 유지된다.

로컬 경로는 디스크의 `/managed` 대신 **로컬 확정 목록 / 이벤트 / [소분류 /] 장비** 브레드크럼으로 표시한다. 앞쪽 이름을 누르면 상위 위치로 돌아가며 선택은 초기화된다.

### NAS 최종 경로 미리보기

파일·폴더를 선택하면 아래 패널에서 NAS에 생성될 최종 경로를 정렬하여 최대 4개와 나머지 파일 수로 확인한다. 총 개수에는 원본과 XMP가 각각 포함된다. 용량은 사진·영상 합계이며 XMP가 있으면 **+ XMP**, 일부 용량을 모르면 별도 안내를 붙인다. 미연결 상태에서는 상대 경로와 연결 안내를 표시한다.

현재 열린 로컬 위치 아래의 상대 구조만 유지하므로 깊은 위치를 열었다면 패널의 기준 안내를 확인한다. 예를 들어 `260903_제주여행 / 해변식당`에서 GoPro 폴더를 골라 NAS의 `Archive`로 보내면 `NAS 루트/Archive/GoPro/파일명`이 된다. 미리보기는 현재 업로드 버튼의 목적지를 기준으로 한다. 다른 원격 폴더에 드롭하면 그 드롭 목적지로 전송한다.

### 업로드와 경로 규칙

보낼 항목 (로컬)의 파일·폴더를 선택하고 **업로드**를 누르면 현재 원격 아카이브 (NAS) 폴더로 전송 작업을 등록한다. 보낼 항목 (로컬) 항목을 원격 아카이브 (NAS)의 빈 영역에 놓으면 현재 폴더에, 특정 폴더 위에 놓으면 그 폴더 아래에 업로드한다. 이미 선택된 항목을 드래그하면 선택 전체를 사용하고, 선택되지 않은 항목을 드래그하면 그 항목을 사용한다. 폴더 선택에는 하위 원본과 XMP가 포함되며, 한 번에 최대 10,000개 파일을 보낼 수 있다.

목적지 아래에는 **현재 보낼 항목 (로컬)에서 보이는 상대 구조**가 붙는다. 따라서 보낼 항목 (로컬)을 어디까지 열었는지에 따라 경로가 달라진다. 예를 들어 논리 경로가 `260903_제주여행/GoPro/GX010001.MP4`이고 원격 아카이브 (NAS)이 아카이브 루트라면 다음과 같다.

| 현재 보낼 항목 (로컬) 위치 | 선택 항목 | 아카이브 루트 아래 생성되는 경로 |
| --- | --- | --- |
| 보낼 항목 (로컬) 루트 | `260903_제주여행` 폴더 | `260903_제주여행/GoPro/GX010001.MP4` |
| `260903_제주여행` 내부 | `GoPro` 폴더 | `GoPro/GX010001.MP4` |
| `260903_제주여행/GoPro` 내부 | `GX010001.MP4` | `GX010001.MP4` |

현재 화면은 업로드 버튼이나 드롭으로 작업을 등록하며, 선택한 파일 중 원격 아카이브의 **다른 경로**에 이미 동일한 파일이 보관되어 있으면 **원격 중복 파일 감지** 대화상자를 열어 기존 원격 경로를 보여 준다. 대화상자에서 **중복 제외하고 신규만 업로드**하거나 **별도 사본으로 모두 업로드**를 선택할 수 있다. 같은 목적지의 동일 내용 파일은 검증 후 건너뛰고(`remote_files`의 크기·수정시각이 그대로이면 즉시 건너뜀), 내용이 다른 동명 파일은 덮어쓰지 않고 실패로 표시한다. 보낼 항목 (로컬) 또는 원격 아카이브 (NAS) 연결 정보가 바뀌면 다시 탐색하거나 연결한 뒤 선택한다.

진행 영역에서 처리 파일 수, 업로드·건너뜀·실패 수, 현재 파일, 전송량과 단계를 확인한다. **업로드 중지**로 중지를 요청할 수 있고, 실패 목록을 펼쳐 경로별 사유를 본다. 완료 후 현재 원격 아카이브 (NAS) 목록이 갱신된다. Incoming 작업과 원격 작업은 각각 한 건씩 동시에 진행할 수 있다.

## 파일 기록

**보유 파일 / 원격 인덱스**는 파일·경로, 분류·작업 정보, 상태·시각의 3컬럼 표로 표시한다. 화면 폭이 760px 이하이면 같은 정보가 세로 카드로 바뀌며 **상세**는 카드 하단에 이어진다. 탭 옆 요약은 현재 탭의 고유 해시·NAS 검증, 검증·실패, 또는 NAS 보관·원격 전용·누락·인덱싱 시각만 보여 준다.

각 행의 **상세**를 펼치면 전체 SHA-256과 **복사** 버튼, 파일 ID, 내부·원래 Incoming 경로, NAS 경로·루트 및 기록 시각을 확인한다. 해시가 없는 기록은 **해시 미기록**으로 표시한다. **복사**는 전체 SHA-256을 복사하며 HTTP LAN 접속에서도 브라우저의 대체 복사 기능을 사용한다. 복사가 불가능하면 알림으로 안내한다. 탭·페이지·폴더 전환과 필터 초기화 시 상세는 접히고, 새로 고침·검색 시 같은 기록의 펼침 상태는 유지한다.

**보유 파일**에서는 관리 원본·XMP와 Incoming 검사 기록을 조회한다. 파일명 옆 **XMP** 태그로 사이드카를 구분하며 같은 해시라도 경로가 다르면 별도 기록이다. 활성 NAS에 사본이 있으면 파일명 아래 **NAS**와 보관 폴더를 표시하고 **NAS 다운로드**를 제공한다. Incoming은 `incoming/...` 경로를 표시하며 관리 파일의 임시 `managed/<ID>`·원래 경로는 상세에서 확인한다. 분류 컬럼은 날짜를 포함한 이벤트·소분류, 이벤트 시간대의 촬영 일시, 장비·크기를 보여 준다. 촬영 시각이 없으면 `—`이며 잘못된 시간대는 앱 시간대로 표시한다.

보관 상태는 **로컬만**, **로컬 + NAS**, **로컬 + 이력**, **NAS 보관**, **로컬 비우기 중**, **로컬 누락**을 구분한다. **로컬 + 이력**의 보조 문구는 다른 루트·과거 이력인지, 검증 이력인지 설명하며 현재 활성 루트 사본 확인과 구별한다. **NAS 보관**의 로컬 비움·활성 루트 미확인 안내와 **로컬 누락**의 NAS 사본·과거 이력 안내를 함께 확인한다. Incoming은 대기·중복·검토·이동 중·이동됨·삭제 중·삭제됨을 표시하며 동일 NAS 파일이 있으면 안내한다. **관리 파일 (로컬·NAS)**·**Incoming 기록**·**NAS 검증 이력 있음**·**XMP**로 필터링할 수 있다.

**작업 내역 → 아카이브 기록**에서는 파일별 목적지 폴더, 이벤트, 작업 번호·종류·크기·장비, 검증 결과·시각과 오류를 조회한다. **업로드 검증**, **동일 파일 확인**, **과거 전송 완료**, **전송 실패**, **진행 대기**, **결과 미기록**을 구분한다. 목적지가 없으면 **목적지 미기록**이며 전체 경로는 마우스를 올리거나 상세에서 확인한다. 과거 자료에 루트가 없으면 **아카이브 루트 미기록**으로 표시한다. 검증은 전송 시점의 기록이며 원격 파일의 현재 상태를 실시간 검사한 결과는 아니다.

**원격 인덱스**에서는 원격 아카이브 스냅샷(`remote_files`)에 등록된 모든 파일과 최근 전체 인덱싱 시각을 조회한다. 원격 경로의 상위 폴더와 연결된 이벤트를 보여 주며 복수 이벤트는 **외 N개**, 미배정 연결은 **외 미배정**·**미배정**으로 표시한다. 전체 이벤트와 파일 ID는 상세에서 확인한다. 카탈로그에 연결되지 않은 파일은 **원격 전용**이다. 왼쪽 원격 폴더 트리(최상위·하위 2단계 및 루트 직속 파일)와 **NAS 보관 / 원격 전용 (카탈로그 미등록) / NAS 누락 / XMP** 필터, 파일명·원격 경로·SHA-256 검색을 사용할 수 있다. Photo Saver 외부에서 올려둔 기존 영상도 원격 인덱싱 후 검색·다운로드·중복 차단에 반영된다.

아카이브·원격 탭의 폴더 위치 우측에 활성 **NAS 루트**를 한 번 표시한다. 같은 루트는 행에서 생략하고, 다른 루트는 **다른 루트:**로 표시한다. 활성 루트 미설정 시 상단에 안내하며 기록에 저장된 개별 루트도 표시한다. 파일명과 경로 basename이 같으면 폴더만 표시하며 루트 바로 아래 파일은 **루트 직속**, 파일명이 다르면 전체 상대 경로를 보존한다.

왼쪽 이벤트·소분류·장비 트리에서 상위 이벤트는 `260903_나고야`, 소분류는 `1일차`처럼 표시한다. 날짜·이벤트명·소분류명으로 검색할 수 있으며 선택한 계층은 목록 위에 표시한다. 필터는 선택 즉시, 검색은 입력 후 280ms(한글 조합 완료 후)에 적용하며 Enter로 즉시 검색한다. 한 페이지는 기본 50개이며 이전·다음으로 이동한다.

## 설정

섹션은 **촬영도구 이름 → 스토리지 연결 → DB 백업 및 복원 → 데이터 초기화** 순서다. 마지막 데이터 초기화는 빨간 경계선과 **위험 구역** 배지로 구분한다.

### 촬영도구 이름

**촬영도구 이름**에서 메타데이터로 감지한 원래 이름과 적용할 이름을 확인한다. 원하는 이름을 입력하고 **이름 저장**을 누르면 기존 파일과 이후 같은 장비명으로 들어오는 파일에 적용된다. 공백은 자동으로 변환하지 않는다. 제조사·모델명이 같은 장비는 하나의 촬영도구로 취급하며, 파일별로 직접 지정한 이름은 유지한다.

이름은 이벤트 목록·필터·아카이브 보낼 항목 (로컬)·파일 기록과 이후 업로드 경로에 적용된다. 배정·확정 상태와 실제 로컬 원본 경로는 유지한다. 기존 원격 폴더와 전송 당시 경로는 바꾸지 않는다. 다른 촬영도구나 관련 이벤트 소분류와 폴더명이 충돌하면 다른 이름을 입력해야 한다. 업로드 대기·실행 중에는 이름을 변경할 수 없다. 이름 규칙은 카탈로그 백업에 포함된다.

### 스토리지 연결

1. **IP 등록 / IP 변경**에서 IPv4 또는 IPv6 주소를 저장한다. 호스트 이름 입력은 지원하지 않는다.
2. **경로 등록 / 경로 변경**에서 원격 저장 절대경로를 입력한다.
3. SSH 계정명은 `.env`의 `PHOTO_SAVER_STORAGE_USER`로 설정한다. 화면에서는 등록 여부만 표시하며 수정하지 않는다.
4. **공개키 생성** 후 **공개키 복사**로 키를 복사해 원격 SSH 계정에 등록한다. 복사는 키마다 한 번만 가능하며, **공개키 재생성**은 확인 후 기존 키를 교체하므로 새 키를 원격에 다시 등록해야 한다.
5. **접속 테스트**를 실행한다. 해당 IP에 저장된 호스트 키가 없을 때 지문 확인 대화상자가 열린다. 서버에서 확인한 지문과 비교한 뒤 **지문 확인 및 접속**을 실행한다. 저장된 키와 서버 키가 다르면 접속을 거부하며, 서버 재설치 등으로 키가 바뀐 경우 **호스트 키 초기화**를 실행한 뒤 다시 접속 테스트로 신뢰할 수 있다.

클립보드 복사에는 브라우저의 클립보드 권한이 필요하다. 키·호스트 확인과 실제 전송의 세부 규칙은 [아카이브·스토리지 문서](archive-and-storage.md)를 참고한다.

### DB 백업과 복원

**DB 백업 다운로드**는 이벤트와 파일 배치가 포함된 SQLite 카탈로그를 내려받는다. 사진·영상과 SSH 설정을 묶어 내려받는 기능은 아니다.

**백업 파일 선택 → 복원**에서 SQLite 파일을 선택하고 확인하면 현재 카탈로그 내용을 교체한다. 원본 파일은 디스크에 남는다. 진행 중인 파일 작업이 있으면 백업·복원 버튼이 비활성화된다.

### 데이터 초기화

초기화는 **설정 → 데이터 초기화** 한 가지다. 확인창에서 **모든 데이터 삭제**를 정확히 입력하고 실행한다. 기존의 기록만 비우기와 managed 되돌리기는 제거했다.

워커는 `managed`의 사진·영상 원본과 XMP·THM·LRV·AAE·숨김 파일, 썸네일과 서버 임시 데이터를 영구 삭제한다. 이어 파일 목록·이벤트·배정·장비/시각 보정·이름 규칙·전송·검증·작업 기록을 모두 비운다. 초기화 작업 자신의 기록도 남기지 않는다. 파일을 다른 폴더로 이동하거나 해시를 계산하지 않는다.

**incoming 디렉터리와 모든 파일·하위 폴더(이전 returned 폴더 포함), SSH 연결 설정·키·호스트 키와 원격 아카이브는 유지한다.** 앱 코드·실행 설정과 저장 영역의 루트 디렉터리도 유지한다. 초기화 중에는 새 파일을 복사하지 않는다. 다른 작업이 진행 중이면 시작할 수 없고, 초기화 중의 변경 요청은 서버가 거부한다.

삭제한 파일은 복구할 수 없다. DB 백업에는 원본 파일이 포함되지 않는다. 중간 실패 시 일부 파일은 이미 삭제되었을 수 있으며 되돌리지 않는다. 오류를 해결한 뒤 같은 초기화를 다시 실행한다. 워커가 중단되면 재시작 시 남은 항목을 계속 삭제한다. 성공 후 **파일 검사**로 보존한 Incoming 파일을 다시 수집할 수 있다. managed에만 있던 원본은 삭제되므로 다시 나타나지 않는다.

## 화면 갱신과 작은 화면

파일 작업 중에는 상태를 반복 조회하고, API 연결 오류가 나면 다시 연결을 시도한다. Incoming에서 파일시스템 변경을 반영하려면 **파일 검사**를 사용한다. 파일 기록과 원격 아카이브 (NAS)의 **새로 고침**은 각각 기록과 원격 목록을 다시 읽는다.

좁은 화면에서는 사이드바가 두 그룹의 위쪽 메뉴로 바뀌고 이벤트·아카이브 영역이 세로로 배치된다. 이벤트 목록은 제한된 높이에서 스크롤하여 파일 목록이 첫 화면에 들어오도록 한다. 가져오기·이벤트 카드의 좌상단 체크 영역은 44×44px이며, 체크 영역은 선택만 하고 나머지 썸네일은 미리보기를 연다. 모바일 내비게이션과 주요 버튼·체크 영역도 최소 44px 높이를 제공한다.

760px 이하에서 가져오기 파일이나 이벤트 파일을 선택하면 선택 도구가 화면 하단에 고정된다. 선택을 해제하면 이벤트 선택 도구는 숨겨지고 가져오기는 목록 아래 안내로 돌아오며, 가져오기의 XMP·동반 파일 탭이나 다른 페이지로 이동할 때 하단 고정도 해제된다. 이벤트 선택 도구는 761px 이상에서도 스크롤 중 하단에 붙는다. 마지막 카드 아래 여백과 기기 안전 영역을 확보하며 알림은 선택 도구 위에 표시한다. 긴 선택 버튼과 NAS 경로는 영역 안에서 줄바꿈한다. 아카이브는 보낼 항목을 선택하고 대상 폴더로 이동한 뒤 **업로드**를 누르며, 데스크톱에서는 드래그도 가능하다. 파일 기록은 모바일에서 카드로, 그 밖의 넓은 표는 가로 스크롤로 확인한다. 프론트엔드는 [HTML](../frontend/index.html), [JavaScript](../frontend/app.js), [CSS](../frontend/styles.css)만으로 구성된다.
## 파일 기록의 썸네일과 캐시 관리

파일 기록은 표 보기와 카드 보기를 제공하고 마지막 선택을 브라우저에 기억한다. 표의 상세는 행 안에서 펼쳐지며 카드의 상세는 대화상자로 열린다. 썸네일 없음 필터는 사진·영상 중 캐시가 없는 항목을 표시한다. XMP는 별도 타일로 표시하며 영상 캐시에는 ▶ 표시가 붙는다.

썸네일 슬롯은 준비됨, 미생성, 생성 중, 생성 불가, 실패·대용량 건너뜀을 구분한다. 실패 사유를 확인하고 다시 시도를 누를 수 있다. 현재 폴더에 생성 가능한 누락 항목이 있으면 상단의 누락 썸네일 생성에서 현재 폴더 또는 전체 범위를 선택한다. 원격 영상은 NAS ffmpeg를 우선 사용하고 미설치 시 기본 150 MiB 이하만 내려받는다. 초과 영상 다운로드 허용은 기본 해제다. 생성 중지는 완료된 캐시를 보존한다.

파일명·썸네일을 누르면 확대 미리보기가 열린다. 로컬 원본이 있으면 사진 원본·영상을 표시하고, 로컬 비움 상태에서는 최대 360×240 캐시와 NAS 원본 다운로드를 제공한다. 캐시가 없으면 지금 썸네일 생성으로 요청할 수 있으며 대화상자를 유지한 채 완료된 이미지로 바뀐다. ←/→와 이전·다음으로 현재 페이지 미디어를 탐색한다.

설정의 썸네일 캐시에서 캐시 수·용량, 미생성, 고아, 실패 현황을 조회하고 일괄 생성·미참조 정리·실패 초기화를 실행한다. DB 백업에 썸네일 이미지 파일은 포함되지 않으므로 복원 후 누락 썸네일 일괄 생성으로 복구한다. 원격 인덱싱에서도 누락 썸네일 함께 생성 옵션을 켤 수 있다.

보유 파일의 **최근 업로드**는 현재 파일 ID·원본/XMP 종류·현재 SHA가 같은 시도 중 작업 번호가 가장 큰 결과다. 저장 상태와 별개이며, 이후 실패나 대기 작업이 과거 성공보다 우선한다. **최근 업로드 결과** 필터는 기존 범위 필터와 함께 적용하고, **폴더 기준 최근 업로드** 집계는 검색·결과 필터와 독립적이다. 원본과 XMP는 별도 자산으로 센다.

**작업 내역**의 **작업 목록 / 아카이브 기록** 탭은 좌우 화살표·Home·End로 전환한다. 작업 카드와 보유 파일 상세의 작업 번호로 정확한 작업의 모든 파일 결과를 연다. 검색·범위·페이지·필터 초기화는 선택한 작업을 유지하며 **전체 아카이브 기록**만 작업 선택을 해제한다. 일부 성공한 실패 작업도 파일별 성공·실패를 그대로 보존하고, 결과가 기록되지 않은 나머지는 실패 대신 결과 미기록으로 표시한다. 과거 전송 완료는 상세 SHA 검증이 없는 호환 이력이며 현재 NAS 사본의 존재를 보장하지 않는다.
## OMV 상태와 기동 기록

사이드바·아카이브·설정은 같은 OMV 상태를 표시합니다. `연결됨`은 인증과 폴더 읽기를 확인한 상태이고, `작동 중 · 연결 가능`은 SSH 서버 응답을 확인한 상태입니다. `부팅 중 · SSH 대기`이면 잠시 기다리세요. `꺼짐 · 응답 없음`은 네트워크 문제일 수도 있습니다. OMV 켜기는 파일 전송을 시작하지 않습니다.

NAS 제목 옆 상태를 누르면 전원·호스트(HA), 아카이브 서버(SSH/SFTP), 최근 기동 기록을 따로 볼 수 있습니다. Escape로 상세를 닫을 수 있습니다. 상세가 접혀 있어도 켜기 요청 → 서버 기동 → 아카이브 연결 단계와 경과 시간, 대기 중지 버튼을 볼 수 있습니다. 마운트 준비 중이면 최대 30초 기다립니다. 대기 중지는 이미 보낸 켜기 요청을 취소하지 않습니다. 설정에서도 같은 진단과 기동 기록을 한곳에서 확인합니다.

오랫동안 켜짐/꺼짐 상태가 유지된 HA 센서는 기본적으로 정상입니다. 관리자가 PHOTO_SAVER_HA_STALE_SECONDS를 양수로 설정한 경우에만 보고 나이 제한을 적용합니다. `보고 지연`·`상태 확인 불가`에서는 상태 확인과 설정 안내를 이용하세요.
