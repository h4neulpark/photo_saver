# 아카이브 전송·스토리지 설정·파일 기록

## OMV 끄기와 종료 확인

아카이브 연결 옆 또는 설정의 **OMV 끄기**를 누르면 취소에 기본 포커스를 둔 확인창을 표시한다. HA 종료 설정이 유효하고 현재 상태가 작동 중이거나 아카이브가 연결돼 있어야 활성화된다. 부팅 중·미확인·오래된 상태에서는 먼저 상태를 확인한다. 원격 작업이나 전체 초기화 중에는 종료할 수 없고, 원격 사본을 검증하는 중복 정리와도 양방향으로 차단한다. 순수 로컬 작업은 병행할 수 있다.

**종료 요청 → 서비스 종료 (SSH) → 전원 차단 확인 (HA)**를 표시한다. SSH는 비인증 TCP 22 배너만 확인하며 SFTP 세션을 열지 않는다. 주소가 있으면 SSH 응답 중단과 fresh HA off가 모두 필요하고, 주소가 없으면 HA off만으로 종료를 확인한다. SSH만 끊긴 채 기한이 지나면 **확인 필요**로 기록하므로 서버 전원 상태를 직접 확인한다. HA on·SSH 미응답이면 최대 15초 기다린 뒤 안전 차단하며 확인할 수 없는 서버에 맹목적으로 종료 스크립트를 보내지 않는다.

종료 중 열린 아카이브 연결과 파일 다운로드는 끊길 수 있다. 확인창은 이 사실과 현재 목록 조회 여부를 안내한다. 종료 확인·이미 꺼짐·SSH만 중단 결과는 기존 디렉터리 목록과 선택을 정리하고 상태 모니터를 강제 새로고침한다. **대기 중지**는 이미 전달된 종료 요청을 취소하지 않는다. 사이드바에는 종료 버튼 없이 호박색 상태와 현재 단계만 표시한다.

## OMV 켜기와 아카이브 준비 상태

아카이브 연결 옆과 스토리지 설정의 **OMV 원격 시작** 행에서 **OMV 켜기**를 누른다. HA 설정만 있으면 SSH 미설정 상태에서도 사용할 수 있다. `POST /api/services/script/turn_on`에 `{"entity_id":"script.wake_omv"}`를 보내며 기존 스크립트를 그대로 재사용한다. 화면 진입·자동 연결·GET은 기동하지 않는다.

UI는 **켜기 요청 → 서버 기동 → 아카이브 연결**을 나누어 표시한다. HA 200은 접수만 뜻하며 script off는 서버 전원 상태가 아니다. 보고 시각은 last_reported(필드 부재 시 last_updated)를 사용한다. 기본 PHOTO_SAVER_HA_STALE_SECONDS=0에서는 장기 안정 on/off도 정상이다. 양수 설정만 나이 제한을 적용하며 파싱 실패·30초 넘는 미래 시각은 stale이다. last_changed는 진단에만 사용한다. 초기 SSH 실패와 60초 넘게 오래된 on이 겹치면 최대 35초 관찰 후 script off일 때 한 번 켜기를 허용한다. 기동 중 유효한 on을 한 번이라도 확인하면 이후 시간 초과는 archive_unconfirmed로 구별한다. script on을 관찰한 작업은 이후 off가 되어도 추가 호출하지 않는다.

접근 ready는 기존 엄격한 호스트 키 정책과 인증으로 SFTP 접속하고 저장 root가 디렉터리이며 최소 한 번의 목록 읽기를 완료한 상태다(빈 폴더도 허용). SSH 인증·호스트 키·경로·권한 문제는 서버 응답과 구별하여 안내한다. 자동 신뢰는 없다. 초기 SFTP ready 또는 명확한 접근 제한이 확인되면 추가 기동은 생략한다. HA 응답만 있는 경우 SSH 설정 필요를 표시하고 업로드를 활성화하지 않는다. 현재 설정으로 성공한 실제 아카이브 조회만 전송 준비에 사용한다.

**대기 중지**는 관찰을 중단한다. 이미 전송한 기동 요청이나 서버 전원은 취소하지 않는다. 응답 유실과 재방문은 GET으로 확인한다. 준비 완료 후에는 같은 대상 revision과 연결 세대가 일치할 때 원격 root 목록을 한 번 갱신하고, 업로드는 사용자가 별도로 시작한다. [운영 설정](setup-and-operations.md#omv-원격-시작-선택-설정)을 참고한다.

이 문서는 현재 코드에 구현된 SSH/SFTP 연결, 원격 탐색, 전송 및 카탈로그 관리 동작을 설명한다. OMV 전용 API를 사용하지 않으므로 SSH와 SFTP를 지원하고 대상 계정이 저장 경로를 읽고 쓸 수 있는 스토리지에 연결할 수 있다.

## 1. 연결 설정

1. `.env`의 `PHOTO_SAVER_STORAGE_USER`에 원격 SSH 계정명을 설정하고 API와 워커에 반영한다.
2. **설정**에서 스토리지 IP와 원격 저장 절대경로를 등록한다. IP는 IPv4 또는 IPv6만 허용하며 호스트명, 포트 지정, scope가 있는 IPv6 주소는 지원하지 않는다. SSH 포트는 기본값인 22번을 사용한다.
3. **공개키 생성**으로 비밀번호가 없는 Ed25519 키 쌍을 만든다. 공개키를 복사해 원격 계정의 SSH 인증 키로 등록한다. 복사 완료를 기록한 뒤에는 앱에서 같은 공개키를 다시 조회할 수 없다. **공개키 재생성**은 기존 키 쌍을 교체하므로 새 공개키를 원격 계정에 다시 등록해야 한다.
4. **접속 테스트**에서 처음 접속하는 IP의 호스트 키 지문을 확인한다. 서버에서 확인한 지문과 비교한 뒤 승인하면 호스트 키를 저장하고 공개키 인증을 테스트한다. 승인 요청은 5분 후 만료된다.
5. **아카이브 전송 → 아카이브 연결**에서 저장 경로의 SFTP 목록을 확인한다. SSH 인증 테스트와 SFTP 접근·쓰기 권한 확인은 별개다.

설정 조회는 계정명과 공개키를 `***`로 반환하고 구성 여부와 현재 IP의 호스트 키 신뢰 여부(`hostKeyTrusted`)를 별도 필드로 제공한다. SSH 테스트는 OpenSSH 명령을, 탐색·다운로드·업로드·오프로드는 Paramiko를 사용한다. 두 경로 모두 앱 전용 개인키와 저장한 호스트 키를 사용하며 SSH agent와 비밀번호 인증을 사용하지 않는다. 저장한 호스트 키가 바뀌면 연결을 거절하며, 설정의 **호스트 키 초기화**(`DELETE /api/settings/ssh-host-key`)로 기존 키를 지운 뒤 접속 테스트로 다시 신뢰할 수 있다.

| 컨테이너 경로 | 내용 |
| --- | --- |
| `/settings/address` | 원격 IP |
| `/settings/remote-root` | 원격 저장 절대경로 |
| `/settings/storage-id` | IP·SSH 키 변경과 무관한 안정적 스토리지 UUID (API 기동 시 1회 생성) |
| `/settings/ssh/id_ed25519` | 앱 전용 개인키 |
| `/settings/ssh/id_ed25519.pub` | 공개키 |
| `/settings/ssh/public_key_copied` | 공개키 복사 완료 표시 |
| `/settings/known-photo-saver-<IP의 SHA-256>` | IP별 승인한 호스트 키 |
| `/settings/pending-host-key.json` | 승인 대기 호스트 키와 만료 토큰 |

Compose의 `settings` 볼륨은 API에 읽기·쓰기, 워커에 읽기 전용으로 마운트한다. 설정 파일 갱신에는 파일 잠금과 임시 파일 교체를 사용한다.

## 2. Source와 Destination

**Source**는 사용자가 이벤트 배치를 확정한 `managed` 파일과 연결된 XMP를 보여 주는 논리 트리다. 실제 원본은 `managed/<파일 ID>/<파일명>`에 있고, Source는 다음과 같이 구성한다.

```text
이벤트 폴더 / 장비 폴더 / 파일명
이벤트 폴더 / 소분류 폴더 / 장비 폴더 / 파일명
```

장비 폴더에는 사용자 지정 장비를 우선 적용하며, 장비를 명시적으로 미상으로 분류하면 `unknown`을 사용한다. 원본과 XMP는 각각 선택할 수 있고, 폴더를 선택하면 그 안의 원본과 XMP를 함께 선택한다.

**Destination**은 설정한 원격 루트 아래 실제 디렉터리를 조회한다. 폴더를 열 때마다 SFTP로 해당 경로의 목록을 읽으며 폴더를 먼저 정렬한다. 파일 크기·수정 시각도 반환한다. 심볼릭 링크는 링크로 표시하고 화면에서 하위 폴더로 열지 않는다. 앱의 `.photo-saver-*.part` 임시 파일을 포함한 숨김 항목도 목록에서 제외하지 않는다.

절대경로와 `..`를 포함한 상대경로를 거절하고, SFTP 정규화 결과가 원격 루트 밖이면 조회를 거절한다. 폴더 목록은 최대 10,000개이며 조회 중 15초가 지나면 시간 초과로 처리한다. 연결·인증 단계는 각각 5초, SFTP 채널은 10초 제한을 사용한다. 목록 응답은 캐시하지 않는다.

## 3. 업로드 목적지와 예약

Source에서 선택한 항목을 **업로드**하거나 Destination의 현재 영역 또는 폴더로 드래그하면 전송을 예약한다. 업로드는 현재 Source 위치를 기준으로 상대 구조를 유지한다.

| 선택 당시 Source 위치 | 선택 파일의 논리 경로 | Destination 위치 | 최종 상대경로 |
| --- | --- | --- | --- |
| 루트 | `260903_여행/GoPro/clip.MP4` | `backup` | `backup/260903_여행/GoPro/clip.MP4` |
| `260903_여행/GoPro` | `260903_여행/GoPro/clip.MP4` | `backup` | `backup/clip.MP4` |

예약 시 서버는 다음 조건을 확인한다.

- 파일이 카탈로그에서 `available`이고 이벤트 배치가 확정됐는지 확인한다.
- 선택한 원본 또는 XMP의 경로와 SHA-256이 있고 현재 Source 하위 항목인지 확인한다.
- 한 요청의 서로 다른 항목이 같은 목적지 경로를 사용하는지 검사한다. 충돌하면 전체 예약을 거절한다. 동일 항목의 중복 선택은 제거한다.
- `allow_duplicates=false`(기본값)이면 `kind=media` 항목의 SHA-256을 현재 저장 루트의 `remote_files(status='present')`와 대조한다. 다른 원격 경로에 이미 같은 파일이 있으면 `409 (code=remote_duplicate)`로 차단하고 기존 원격 경로 목록을 반환한다. 화면에서는 중복을 제외하고 신규만 올리거나 별도 사본으로 모두 올릴 수 있다.
- Destination 조회 시 받은 연결 버전이 현재 설정과 같은지 확인한다. IP·계정·저장 루트·호스트 키·공개키 식별자로 연결 버전을 계산한다.

한 요청은 최대 10,000개 항목이다. 예약하면 목적지, 로컬 경로, SHA-256, 원본 fingerprint를 작업 payload에 고정한다. 설정 원문 대신 연결 버전 해시를 저장하며, 실행 전에 설정이 달라졌으면 실패한다. 이후 이벤트 이름이나 배치를 바꿔도 이미 예약한 목적지는 유지된다.

업로드·오프로드·원격 인덱싱은 원격 레인에서 하나씩 실행하며, Incoming 작업 한 건과 동시에 실행할 수 있다. 중복 정리에서 남길 managed 사본과 같은 파일의 오프로드는 중복 정리가 끝난 뒤 예약한다.

## 4. SFTP 전송·검증·다운로드·로컬 원본 비우기

워커는 예약한 항목을 순서대로 처리한다.

1. 원격 저장 루트를 정규화하고 필요한 하위 디렉터리를 만든다. 하위 경로에 일반 파일이나 심볼릭 링크가 있으면 실패한다.
2. 원본의 fingerprint를 확인하고 검증한 파일 디스크립터를 전송이 끝날 때까지 유지한다. XMP는 실행 시 fingerprint를 확보하고 예약된 SHA-256과 대조한다.
3. 목적지에 같은 이름의 일반 파일이 있으면 크기를 확인한다. `remote_files`에 같은 `(storage_id, path, archive_root, sha, size, mtime_ns)` 검증 기록이 이미 있으면 원격 해시를 다시 계산하지 않고 즉시 `skipped`로 건너뛴다. 기록이 없거나 `mtime_ns`가 바뀌었다면 원격 해시를 비교해 일치하면 `skipped`, 내용이 다르거나 일반 파일이 아니면 덮어쓰지 않고 실패한다.
4. 새 파일은 같은 디렉터리의 `.photo-saver-<작업 토큰>-<항목 번호>.part`에 배타적으로 생성한다. 같은 작업의 이전 임시 파일만 제거하고 처음부터 다시 쓴다.
5. 1 MiB 단위로 전송하면서 로컬 SHA-256과 크기를 검증하고 전송 후 fingerprint를 재확인한다.
6. 원격 해시 비교·검증은 이미 인증된 SSH 세션에서 `sha256sum` 또는 `shasum -a 256` 실행을 우선 시도한다. SFTP 전용 계정 등 원격 명령을 사용할 수 없는 환경에서는 `stream.prefetch(size)`를 켠 SFTP 재읽기로 자동 폴백하며 진행률을 실시간으로 표시한다. 검증에 성공한 뒤 덮어쓰지 않는 SFTP `rename`으로 최종 이름을 게시하고 `uploaded`로 기록한다. 성공(`uploaded`·`skipped`) 시 `storages`와 `remote_files` 스냅샷도 함께 갱신한다.
7. 전송 도중 SFTP 채널이 끊기거나 통신 수준 오류가 발생하면 남은 파일마다 실패 행을 반복 기록하지 않고 즉시 작업을 `failed`로 종료한다.

### 단일 파일 SFTP 다운로드

- `GET /api/archive/download`는 `path`(현재 저장 절대경로 기준 상대경로) 또는 `media_id`(+`kind=media|xmp`)로 원격 정규 파일을 스트리밍 다운로드한다.
- 모든 상위 디렉터리와 대상 파일에 `lstat`을 수행해 심볼릭 링크, 디렉터리, 루트 이탈 경로를 차단한다. `media_id` 조회 시 현재 설정된 `archive_root`와 다른 경로에만 보관된 파일은 409로 거부한다.
- RFC 5987 UTF-8 `Content-Disposition`, `Content-Length`, `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`를 설정하며, Destination 탐색기·이벤트 관리·파일 기록에서 바로 내려받을 수 있다.

### 원격 아카이브 증분 인덱싱 (`remote-index`)

- `POST /api/archive/index`는 현재 연결 버전이 유효한 원격 저장소에서 전체 아카이브 루트 또는 선택한 하위 폴더를 비동기 스캔한다.
- 워커는 SFTP `listdir_iter`로 대상 범위를 순회하며 지원 확장자(`.jpg`, `.jpeg`, `.png`, `.webp`, `.heic`, `.heif`, `.mp4`, `.mov`, `.xmp`)의 정규 파일만 수집한다. `.DS_Store`, `._*`, `.AppleDouble`, `.photo-saver-*.part` 등 `.`로 시작하는 숨김 파일·폴더와 심볼릭 링크·비정규 파일은 건너뛴다. 한 번의 스캔 상한은 200,000개다.
- `full_rehash=false`(기본값)이면 현재 `remote_files`에 `status='present'`와 SHA-256이 기록되어 있고 `(size, mtime_ns)`가 동일한 파일은 원격 해시를 생략하고 `last_seen_at`만 배치 갱신한다.
- 신규 파일, 크기가 바뀌거나 수정된 파일, 또는 `full_rehash=true` 대상은 업로드와 동일한 SSH 우선(`sha256sum`·`shasum -a 256`) / SFTP `prefetch()` 자동 폴백 경로로 SHA-256을 계산한다. 해시 완료 직후 `lstat`을 다시 확인해 도중에 변경된 파일(TOCTOU)은 기록하지 않고 실패로 보고한다.
- 취소나 SFTP 연결 단절 없이 범위 순회와 처리가 끝난 경우에만 스캔 범위 내에서 발견되지 않은 기존 `present` 행을 `missing`으로 전환한다. 범위 밖의 형제·상위 폴더 행은 건드리지 않으며, 취소·단절 시에는 이미 기록한 해시만 유지하고 기존 `present` 행을 `missing`으로 바꾸지 않는다. 전체 루트 스캔 완료 시 `storages.last_indexed_at`을 기록한다.
- 이렇게 인덱싱된 기존 원격 파일은 Photo Saver를 거치지 않고 미리 올려둔 영상이라도 Incoming 중복 차단, 업로드 타 경로 중복 차단, `파일 기록 → 원격 인덱스` 검색·다운로드에 즉시 반영된다.

### 로컬 원본 비우기 (Safe Offload)

- `POST /api/jobs/offload`는 현재 활성 저장 루트의 `remote_files(status='present')`에 검증된 사본이 있는 `available` 파일만 받는다. 연결된 XMP가 있는 파일은 XMP도 함께 아카이브에 검증·보관되어 있어야 한다.
- 워커는 삭제 직전 원격 SFTP에 연결해 상위 경로와 대상 파일의 `lstat`(정규 파일·크기 일치, 심볼릭 링크 거부)을 실시간으로 확인하고, 로컬 파일의 fingerprint와 SHA-256을 재검증한 뒤에만 로컬 원본(및 XMP)과 빈 `managed/<ID>` 디렉터리를 삭제한다.
- 원격에서 파일이 사라졌거나 크기가 다르면 해당 `remote_files` 행을 `missing`으로 갱신하고 로컬 원본은 삭제하지 않는다.
- 비우기가 끝나면 `media.status='archived'`로 전환하며 썸네일, 메타데이터, XMP 메타데이터와 이벤트 배정은 유지한다. 중단 후 재시작 시 `offloading` 상태에서 멱등 복구한다.

원격 명령 실행(`sha256sum`·`shasum -a 256`)이 허용되는 스토리지에서는 검증 시 영상 바이트를 Mac으로 다시 내려받지 않는다. 원격 명령이 거부되거나 지원되지 않으면 세션 내에서 자동으로 SFTP `prefetch()` 검증으로 전환된다. 전송 중 목적지 파일이 새로 생기면 최종 이름 변경이 실패하며 기존 파일을 보존한다.

진행 결과는 현재 경로, 단계, 전체·완료 파일 수, 업로드·건너뜀·실패 수, 바이트 수를 포함한다. 진행 갱신은 최대 약 0.3초 간격으로 제한하며 파일별 경계에서는 즉시 저장한다. 건너뛴 파일도 처리한 바이트에 포함되므로 화면 수치는 실제 네트워크 송신량과 다를 수 있다. 오류 상세는 최대 100개를 보관한다.

## 5. 실패·취소·재시작

| 상태 | 동작 |
| --- | --- |
| `queued` | 아직 워커가 실행하지 않은 상태. 취소하면 즉시 `cancelled`로 바뀐다. |
| `running` | 실행 중. 취소 요청을 저장하면 워커가 다음 진행 저장 시 확인해 중단한다. |
| `done` | 모든 항목이 `uploaded` 또는 `skipped`로 처리됐다. |
| `failed` | 파일별 실패나 연결 오류가 발생했다. 파일별 실패 후에는 다음 파일 처리를 시도하며, 일부 성공도 그대로 남는다. |
| `cancelled` | 사용자가 중단했다. 이미 게시된 파일과 기록은 유지한다. |

전송 함수가 정상적으로 종료되거나 예외로 빠져나올 때는 해당 임시 파일 삭제를 시도한다. 프로세스 강제 종료나 통신 단절로 남은 임시 파일은 같은 작업을 재실행할 때 정리한다. 다른 작업의 임시 파일을 일괄 삭제하는 기능은 없다.

워커 재시작 시 `running` 작업을 `queued`로 돌리고 같은 payload를 다시 처리한다. 이미 최종 파일이 있으면 해시를 비교해 건너뛰고, 미완료 파일은 처음부터 보낸다. 바이트 위치부터 이어 보내지는 않는다. 최종 게시 직후 기록 전에 중단됐어도 재실행 시 동일 파일 검증으로 복구할 수 있다.

스토리지 전원이 꺼졌거나 연결에 실패한 작업은 `failed`가 된다. 자동 대기·백오프·재연결 예약은 없으므로 연결을 복구한 뒤 사용자가 다시 업로드해야 한다. 업로드는 로컬 원본이나 완료한 원격 파일을 삭제하지 않는다.

## 6. 파일 기록과 검증 이력

**파일 기록**은 SQLite 카탈로그를 조회하며 원격 스토리지에 연결하지 않는다.

- **보유 파일**: `managed` 원본, 연결된 XMP, 해시가 기록된 Incoming 검사 항목을 경로별로 표시한다. 파일명·현재/원래 경로·SHA-256·장비·이벤트·파일 ID로 검색하고 **관리 파일 (로컬·NAS)**, **Incoming 기록**, **NAS 검증 이력 있음**, **XMP**로 필터링한다. 기본 경로는 활성 NAS 사본의 영구 상대 폴더 또는 `incoming/...`이며 내부 관리 경로·원래 Incoming 경로는 상세에 둔다. 촬영 시각은 사용자 지정 → 원본 메타데이터 → 유효한 XMP `date.time` 순으로 선택하고 상위 이벤트 시간대를 적용한다.
- **작업 내역 → 아카이브 기록**: 파일·목적지 폴더, 이벤트·작업 번호·종류·크기·장비, 결과·시각·오류의 3컬럼으로 표시한다. 전체 해시, 로컬·원래 Incoming 경로, 당시 루트·목적지, 검증·기록 시각은 **상세**에서 확인한다. 이벤트·소분류·장비 트리와 페이지 이동을 제공한다. 기본 페이지 크기는 50개, API 상한은 100개다.
- **원격 인덱스**: `remote_files` 스냅샷의 모든 파일(업로드·증분 인덱싱으로 등록된 기존 원격 파일 포함)을 원격 경로 2단계 폴더 트리와 함께 조회한다. **NAS 보관**, **원격 전용 (카탈로그 미등록)**, **NAS 누락**, **XMP** 필터와 파일명·원격 경로·SHA-256 검색, 현재 활성 저장 루트에 대한 직접 다운로드를 제공한다. 원본·XMP SHA와 `available`·`archived` 미디어를 연결해 이벤트를 표시하며 `missing`·`offloading`만 매칭되거나 SHA가 없으면 미연동이다. 복수 이벤트·미배정 연결을 구분하고 상세에서 모든 이벤트·파일 ID·스토리지 ID·확인 시각을 조회한다.

상위 이벤트 라벨은 저장 폴더명(`260903_나고야`), 소분류는 이름(`1일차`)을 사용하며 파일에는 `260903_나고야 / 1일차`로 표시한다. 날짜 접두도 검색된다. 폴더 트리는 이벤트·소분류·장비 아이콘과 굵기로 계층을 구분한다. 아카이브·원격 탭은 활성 **NAS 루트**를 상단에 한 번 표시하고 동일 루트는 행에서 생략한다. 다른 루트는 별도 안내하며 활성 루트가 없으면 미설정 안내와 개별 기록 루트를 표시한다. 루트의 trailing slash는 표시 비교에서 정규화하되 `/`는 유지한다. API 다운로드 가능 여부는 기존 활성 루트 일치 계약을 유지한다.

각 행의 **상세**는 전체 SHA-256과 복사를 포함한 기록 정보를 펼친다. 탭·페이지·폴더 전환과 필터 초기화는 상세를 접고, 조회 성공 시 남은 행의 펼침 상태만 유지한다. 좁은 화면에서는 3컬럼을 카드로 표시하고 상세를 카드 하단에 연결한다.

| 파일별 결과 | 의미 |
| --- | --- |
| `uploaded` | 새 파일을 업로드하고 해시를 검증했다. |
| `skipped` | 같은 목적지의 기존 파일과 로컬 파일이 예약된 해시와 일치했다. |
| `failed` | 해당 파일 처리에서 오류가 기록됐다. 검증 시각은 없다. |
| `legacy_verified` | 파일별 기록이 없는 과거 `done` 작업에서 복원한 완료 이력이다. 당시 원격 루트가 없을 수 있다. |
| `pending` | 파일별 기록이 없고 작업이 `queued` 또는 `running`이다. |
| `unknown` | 파일별 기록이 없는 실패·취소 작업 등의 항목이다. |

파일별 전송 결과는 `archive_entries`에 작업 ID와 항목 번호를 키로 저장한다. 작업 전체가 연결 단계에서 실패한 경우 모든 항목에 개별 `failed` 행을 만들지는 않으며, 기록 화면은 작업 payload를 보완 조회해 `unknown` 등으로 표시한다. 과거 형식의 전송도 같은 방식으로 표시한다.

검증 이력은 전송 당시의 사실이다. 현재 원격 파일의 존재·내용을 주기적으로 다시 확인하지 않는다. 보유 파일의 `has_archive`는 파일 ID·원본/XMP 종류·현재 SHA-256이 검증 이력과 일치하거나 동일 SHA의 `present` 원격 인덱스가 있으면 참이다. **로컬 + NAS**는 활성 루트에 내려받을 사본이 있는 경우이며 **로컬 + 이력**은 검증 기록은 있으나 활성 루트 사본을 확인하지 못한 경우다. **로컬만**, 로컬을 비운 **NAS 보관**, **로컬 누락**도 별도로 구분하고 분류 확정·미확정과 로컬 비움·NAS 사본·과거 이력 안내를 함께 제공한다. 기록 화면의 이벤트와 장비 분류는 현재 카탈로그를 따르고, 전송 당시 목적지 경로는 이력에 남는다.

## 7. 카탈로그 백업과 복원

**설정 → DB 백업 다운로드**는 SQLite Online Backup API로 일관된 `.sqlite3` 파일을 만든다. 파일명은 앱 기본 시간대 기준 `photo-saver-YYYYMMDD-HHMMSS.sqlite3`이며 응답 후 서버 임시 파일을 삭제한다. 백업과 복원 모두 전체 카탈로그 잠금을 사용하고, 현재 `queued` 또는 `running` 작업이 있으면 거절한다.

**백업 파일 선택 → 복원**은 최대 128 MiB의 SQLite 파일을 받아 현재 스키마의 데이터로 복사한다. 현재 카탈로그 데이터는 복원 내용으로 대체된다. 복원은 다음을 검사하고 한 트랜잭션으로 적용한다.

- SQLite `quick_check`, 필수 테이블과 컬럼, JSON 필드의 형식, 외래 키 관계를 검증한다.
- 이전 백업에서 빠질 수 있는 XMP·원래 경로 관련 컬럼과 `scan_xmp`, `archive_entries` 테이블을 허용한다.
- 백업 안의 `queued`·`running` 작업은 `failed`로 바꾼다. 이전 작업을 자동 재실행하지 않는다.
- 복원한 `media.moving`은 `missing`, `scan_files.deleting`은 `review`로 바꾼다. 복원 뒤 라이브러리를 새로 고쳐 실제 파일 상태를 확인한다.

백업 대상은 카탈로그 데이터다. 사진·영상·XMP 원본, 썸네일, `.env`, `/settings`의 IP·저장 경로·SSH 키·호스트 키는 포함하지 않는다. 복원은 해당 파일이나 원격 아카이브를 복구하지 않는다.

## 8. 현재 범위와 후속 설계

루트 README의 초기 설계 중 다음 항목은 현재 구현에 포함되지 않는다.

- rsync 전송과 원격 전용 보조 에이전트·데몬.
- 다른 원격 경로에서 동일 콘텐츠를 찾아 스토리지 내부에서 복사하거나 하드링크로 재사용하는 기능(현재는 중복을 감지·차단하고 선택적 별도 사본 업로드만 지원).
- 충돌 파일에 해시 접미사를 붙이는 자동 이름 변경과 재승인 미리보기.
- OMV가 꺼진 동안 자동 대기하고 재시도하는 전송 스케줄러.

현재 지원하는 중복 재사용은 **선택한 동일 목적지 경로의 파일**을 전송 시점에 검증해 건너뛰는 동작이며, 다른 원격 경로의 중복 파일은 Incoming 수집 및 업로드 예약 단계에서 전역으로 감지·차단한다.

## 인덱싱과 썸네일

원격 인덱싱 다이얼로그의 누락 썸네일 생성은 기본 해제이며 선택을 브라우저에 기억한다. 해시·증분 갱신 후 열려 있는 동일한 SFTP/SSH 연결에서 누락 썸네일을 생성한다. 기존 unchanged 파일도 대상에 포함되고 이미 있는 캐시는 재사용한다. 별도 썸네일 작업은 원격 대상이 하나라도 있으면 remote 레인을 사용한다.

원격 파일은 반드시 `resolve_remote_file`로 루트 하위 경로·상위 디렉터리·일반 파일을 확인하고 심볼릭 링크를 거부한다. SSH ffmpeg는 경로를 `shlex.quote`한 위치 인자로 전달하고 `-protocol_whitelist file`로 입력의 네트워크 프로토콜을 차단한다. 프레임은 바이트 그대로 게시하지 않고 Pillow로 검증·재인코딩한다. 종료 코드 126/127의 미설치 상태는 같은 작업에서 기억하여 이후 영상은 SFTP 폴백을 사용한다. 기본 150 MiB 제한을 초과하는 폴백은 일괄 생성 다이얼로그에서 별도로 허용해야 한다.

보유 파일의 **최근 업로드**는 현재 파일 ID·원본/XMP 종류·현재 SHA가 같은 시도 중 작업 번호가 가장 큰 결과다. 저장 상태와 별개이며, 이후 실패나 대기 작업이 과거 성공보다 우선한다. **최근 업로드 결과** 필터는 기존 범위 필터와 함께 적용하고, **폴더 기준 최근 업로드** 집계는 검색·결과 필터와 독립적이다. 원본과 XMP는 별도 자산으로 센다.

**작업 내역**의 **작업 목록 / 아카이브 기록** 탭은 좌우 화살표·Home·End로 전환한다. 작업 카드와 보유 파일 상세의 작업 번호로 정확한 작업의 모든 파일 결과를 연다. 검색·범위·페이지·필터 초기화는 선택한 작업을 유지하며 **전체 아카이브 기록**만 작업 선택을 해제한다. 일부 성공한 실패 작업도 파일별 성공·실패를 그대로 보존하고, 결과가 기록되지 않은 나머지는 실패 대신 결과 미기록으로 표시한다. 과거 전송 완료는 상세 SHA 검증이 없는 호환 이력이며 현재 NAS 사본의 존재를 보장하지 않는다.
## OMV 현재 상태 확인

NAS 제목 옆 상태 필은 사이드바·설정과 같은 상태를 표시한다. 실제 아카이브 조회 성공은 `연결됨`, HA on인데 SSH가 응답하지 않으면 `부팅 중 · SSH 대기`, SSH 배너 도달은 `작동 중 · 연결 가능`이다. 배너 조회는 인증·SFTP·디스크 읽기를 하지 않는다. HA off와 SSH 도달이 겹치면 SSH를 우선하고 ha_lagging을 진단에 남긴다. `꺼짐 · 응답 없음`은 네트워크 실패 가능성도 포함한다.

상태 필을 누르면 전원·호스트(HA), 아카이브 서버(SSH/SFTP), 최근 기동 기록을 따로 볼 수 있으며 Escape로 닫는다. 상세가 접혀 있어도 기동 스텝퍼·경과 시간·대기 중지가 보인다. 기동 후 저장 경로가 아직 없거나 SFTP가 준비되지 않으면 `스토리지 마운트 대기 중`으로 최대 30초 재시도한다. 인증·호스트 키·권한·디렉터리 오류는 즉시 접근 제한으로 표시한다. 상태 확인과 기동 완료는 자동 업로드를 실행하지 않는다.

상태는 기동 작업 이력 없이도 조회한다. 펼침 안의 최근 기동 작업은 과거 기록으로 구분하며, 진행 중의 `대기 중지`는 상세를 접어도 그대로 사용할 수 있다. 중지는 해당 작업 ID의 대기만 멈추며 이미 보낸 켜기 요청을 취소하지 않는다. 설정과 사이드바/모바일 상단의 요약도 같은 상태를 공유한다.
