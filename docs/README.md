## 초기 설계와의 차이

다음 항목은 현재 코드에 구현되어 있지 않다.

- rsync 전송, 원격 보조 스크립트, 원격 서버에서의 해시 계산과 원격 전체·증분 인덱싱.
- OMV 전원이 꺼진 동안 연결을 기다리며 자동으로 재시도하는 예약 전송과 백오프.
- 원격의 다른 경로에서 같은 해시를 찾아 재사용하거나 서버 내부에서 복사하는 기능.
- 동명 충돌에 해시 접미사를 자동으로 붙이는 기능과 별도 전송 미리보기·승인 단계.
- 분석과 전송의 동시 실행. 현재는 작업 종류 전체를 합쳐 `queued` 또는 `running` 작업을 하나만 허용한다.
- 별도 장비 등록부·파일명 기반 장비 규칙, 사용자 로그인과 다중 사용자 권한 관리.

실제 업로드는 **Paramiko SFTP**로 전송하고, 원격 SSH 세션에서 `sha256sum`·`shasum -a 256` 실행이 가능하면 서버 측에서 해시를 검증하며 SFTP 전용 서버 등에서는 `prefetch()` 기반 SFTP 재읽기로 자동 폴백한다. 이미 `remote_files`에 검증 기록이 있고 원격 `lstat`의 `(size, mtime_ns)`가 일치하는 동일 경로 파일은 재읽기 없이 즉시 건너뛴다. 대상 경로의 내용이 다르면 기존 파일을 보존하고 해당 파일을 실패로 기록한다. 파일 기록의 검증 표시는 과거 검증 이력이며 원격 파일의 현재 존재 여부를 보장하지 않는다.

Incoming 파일별 기록과 XMP 연결 후보는 최신 완료 검사만 보관한다. 새 검사가 완료되면 이전 `scan_files`·`scan_xmp` 행을 제거하므로 삭제한 사진 등의 과거 Incoming 기록을 계속 보존하는 기능은 없다. 작업 요약(`jobs`)과 `managed` 카탈로그, 아카이브 전송 이력은 별도로 유지한다.

## 문서 갱신 기준

동작을 바꿀 때 관련 기능 문서와 [API](api.md)·[데이터 모델](data-model.md)을 함께 확인한다. 환경 변수나 마운트를 바꾸면 [실행과 운영](setup-and-operations.md)을 갱신한다. 미구현 아이디어는 구현 설명과 분리하고, 실제 `.env` 값·SSH 키·개인 경로는 문서에 넣지 않는다.
