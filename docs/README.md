# Photo Saver 구현 문서

## Incoming 기기 업로드

Mac·iPad·iPhone의 사진·영상 및 XMP·THM·LRV를 Incoming의 **기기에서 업로드**로 받는다. 청크 임시 저장·원자적 게시·충돌 개명·동반 파일 리매핑·진행률·취소·오프셋 재시도와 완료 후 파일 검사를 지원한다. 사용법은 [사용자 가이드](user-guide.md), 프로토콜은 [API](api.md), 마운트·Nginx·청소 정책은 [실행과 운영](setup-and-operations.md), 테스트는 [개발과 검증](development.md)을 따른다.

이 문서는 저장소에 구현된 동작을 코드 기준으로 정리한다. 기준일은 **2026-11-24**이다. 루트 [README](../README.md)의 초기 설계에 포함된 향후 기능과 현재 구현을 구분한다.

## 초기 설계와의 차이

다음 항목은 현재 코드에 구현되어 있지 않다.

- rsync 전송과 원격 보조 스크립트(전용 에이전트 데몬).
- OMV 전원이 꺼진 동안 연결을 기다리며 자동으로 재시도하는 예약 전송과 백오프.
- 원격의 다른 경로에서 같은 해시를 찾아 스토리지 내부에서 복사하거나 하드링크로 재사용하는 기능(현재는 중복을 감지·차단하고 선택적 별도 사본 업로드만 지원).
- 동명 충돌에 해시 접미사를 자동으로 붙이는 기능과 별도 전송 미리보기·승인 단계.
- 별도 장비 등록부·파일명 기반 장비 규칙, 사용자 로그인과 다중 사용자 권한 관리.

실제 업로드는 **Paramiko SFTP**로 전송하고, 원격 SSH 세션에서 `sha256sum`·`shasum -a 256` 실행이 가능하면 서버 측에서 해시를 검증하며 SFTP 전용 서버 등에서는 `prefetch()` 기반 SFTP 재읽기로 자동 폴백한다. 원격 아카이브 증분 인덱싱(`remote-index`)도 같은 SSH/SFTP 해시 경로를 사용해 Photo Saver 외부에서 미리 올려둔 기존 파일까지 `remote_files`에 색인한다. 이미 `remote_files`에 검증 기록이 있고 원격 `lstat`의 `(size, mtime_ns)`가 일치하는 파일은 업로드·증분 인덱싱 모두 재읽기 없이 즉시 건너뛴다. 대상 경로의 내용이 다르면 기존 파일을 보존하고 해당 파일을 실패로 기록한다. 파일 기록의 검증 표시는 과거 검증 이력이며 원격 인덱스는 마지막 인덱싱·업로드 시점의 스냅샷이다.

Incoming 파일 목록과 XMP 연결 후보는 최신 완료 검사를 기준으로 한다. 새 검사가 완료되면 이전 `scan_files`·`scan_xmp` 행을 제거한다. 이동·정리·삭제·XMP 연결의 처리 결과는 작업 기록(`jobs`)에 남고 Incoming 화면에서 최근 결과를 확인할 수 있다.

## 문서 갱신 기준

동작을 바꿀 때 관련 기능 문서와 [API](api.md)·[데이터 모델](data-model.md)을 함께 확인한다. 환경 변수나 마운트를 바꾸면 [실행과 운영](setup-and-operations.md)을 갱신한다. 미구현 아이디어는 구현 설명과 분리하고, 실제 `.env` 값·SSH 키·개인 경로는 문서에 넣지 않는다.
